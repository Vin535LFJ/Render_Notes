# GPU 图像处理算法

> **定位**：把常见图像处理算法映射到 GPU 的并行模型上，给出复杂度、带宽与工程取舍。重点不是推导公式，而是判断"这个算法在移动端能不能实时跑、瓶颈在哪"。

## 1. GPU 图像算法的三个约束

### 1.1 数据并行与邻域

| 算法类型 | 每个输出像素依赖 | GPU 友好度 |
|---|---|---|
| 逐像素（调色、LUT、色调映射） | 仅自身 | 极高 |
| 固定邻域（卷积、锐化） | 邻域 N×N | 高，受纹理缓存影响 |
| 全局/迭代（直方图、NLM、光流） | 全图或多轮迭代 | 低，需要多 pass / 规约 |

GPU 的强项是"同一段代码作用于百万像素"；弱项是"全局同步"和"数据依赖链"。设计算法时优先把全局操作改写成多 pass 规约或近似。

### 1.2 带宽是主要成本

一次全屏 pass 的读写量：

$$
B = W \times H \times C \times b \times (1 + k)
$$

- `C` 通道数，`b` 每通道字节数，`k` 为读写次数（读源 + 写目标 = 2，若读写同一附件则更高）。
- 1080p RGBA8、单次读写约 `1920×1080×4×2 ≈ 16.6 MB`。
- 30 个全屏 pass ≈ 500 MB/帧；60 FPS ≈ 30 GB/s，已接近移动端 LPDDR 带宽的可用上限 ⚠️。

**结论**：图像算法的第一优化目标通常是**减少 pass 数和分辨率**，而不是减少 ALU 指令。

### 1.3 精度与格式

| 场景 | 推荐格式 |
|---|---|
| 中间 HDR 结果 | RGBA16F / R11G11B10F |
| 仅亮度/系数 | R8 / R16F |
| 最终显示 | RGBA8（sRGB 编码） |
| 深度/视差 | R16F / R32F（按范围） |

- 中间结果用 8bit 会在多 pass 后累积量化误差，出现 banding。
- 移动端 `RGBA16F` 的带宽是 `RGBA8` 的两倍，能用 `R11G11B10F` 就别用 16F。

## 2. 可分离卷积

### 2.1 原理

二维高斯核可分解为两个一维核：

$$
G_{\sigma}(x,y) = G_{\sigma}(x) \cdot G_{\sigma}(y)
$$

因此 `N×N` 卷积可拆成"水平 N + 垂直 N"，复杂度从 `O(N²)` 降到 `O(2N)`：

| 核半径 | 朴素 2D | 可分离 |
|---|---|---|
| 5×5 | 25 次采样 | 10 次 |
| 9×9 | 81 次 | 18 次 |
| 21×21 | 441 次 | 42 次 |

### 2.2 实现要点

```glsl
// 水平 pass
vec4 sum = vec4(0.0);
for (int i = -R; i <= R; ++i) {
    sum += texture(u_src, v_uv + vec2(float(i) * u_texel.x, 0.0)) * u_weights[i + R];
}
```

- 两个 pass 之间需要一张中间纹理（或 ping-pong）。
- 中间纹理的精度不能低于最终结果，否则会引入方向性误差。
- 高斯核的权重和为 1；分离后每个一维核也应为 1。
- 大核（如 Bloom 的 40+ 半径）可用"降采样 + 小核"近似，既省带宽又扩大感受野 ✅。

### 2.3 其他可分离/可近似核

| 算法 | 是否可分离 | 备注 |
|---|---|---|
| Box blur | 是 | 可用前缀和/积分图 O(1) |
| Gaussian | 是 | 最常用 |
| Sobel | 是（两个 1D 核组合） | 边缘检测 |
| Bilateral | 否（权重依赖像素值） | 需近似或降维 |
| Median | 否 | 可用排序网络/近似 |

## 3. 双边滤波与引导滤波

### 3.1 双边滤波

$$
I'(p) = \frac{1}{W_p}\sum_{q \in \Omega} I(q)\,
G_{\sigma_s}(\|p-q\|)\,
G_{\sigma_r}(|I(p)-I(q)|)
$$

- 空间核 `σs` 控制邻域范围，值域核 `σr` 控制"只平滑相似像素"。
- 因此能保边：边缘两侧像素值差大，权重趋近 0。
- 复杂度 `O(N²)` 且不可分离，实时大核很贵。

**工程近似**：

| 方法 | 思路 | 代价 |
|---|---|---|
| 分离近似 | 先水平后垂直，值域权重用上一次结果 | 质量下降 |
| 降采样 | 在半分辨率做双边，再上采样 | 边缘略糊 |
| 快速双边（permutohedral） | 高维网格插值 | 实现复杂 |
| 联合双边 | 用另一张引导图（如深度/亮度）算值域权重 | 保边更好 |

### 3.2 引导滤波

局部线性模型：`q_i = a_k I_i + b_k`，在窗口 `ω_k` 内最小化 `(q - p)²`。核心是多次盒滤波，复杂度与窗口大小无关（`O(1)` per pixel）：

```
mean_I  = boxfilter(I)
mean_p  = boxfilter(p)
corr_I  = boxfilter(I*I)
corr_Ip = boxfilter(I*p)
a = (corr_Ip - mean_I*mean_p) / (corr_I - mean_I*mean_I + eps)
b = mean_p - a*mean_I
q = boxfilter(a)*I + boxfilter(b)
```

| 特性 | 双边 | 引导 |
|---|---|---|
| 保边 | 是 | 是（epsilon 控制） |
| 复杂度 | 随核增大 | 与核无关 |
| 光晕 | 较少 | 可能出现 |
| 典型用途 | 美颜、降噪 | 抠图、去雾、HDR 细节增强 |

**移动端建议**：优先引导滤波或降采样双边；全分辨率大核双边在 1080p 上很难稳定 60 FPS ⚠️。

## 4. 3D LUT

### 4.1 作用

把任意逐像素颜色映射（调色、色调映射、色彩空间转换）烘焙成三维查找表：

```
output = LUT[input.r][input.g][input.b]
```

- 常见尺寸：17³、33³、65³。
- 65³ × RGBA8 ≈ 1.1 MB；33³ ≈ 144 KB。
- 存储为 2D 图集（如 8×8 个 64×64 切片），shader 里做三线性或四面体插值。

### 4.2 采样要点

- 三线性插值需要 8 次采样；四面体插值 4 次，且对颜色更准确。
- UV 的半个纹素偏移不能忘，否则切片边界会串色。
- LUT 的输入必须是**归一化到 [0,1] 的编码值**，且要明确它作用在 sRGB 还是线性空间。
- HDR 输入超出 [0,1] 时，LUT 无法表达，需要先 tone map 或分段处理。

shader 实现见 [05-Shader 题库 §2.5](../06-面试知识库/车载渲染引擎/05-Shader编程与手写题库.md#25-3d-lut-调色)。

### 4.3 生成方式

| 方式 | 说明 |
|---|---|
| 离线烘焙 | Photoshop/DaVinci 导出 `.cube`，运行时转图集 |
| 运行时生成 | 用一个 pass 渲染 LUT 体积，适合动态参数 |
| 解析近似 | 用曲线/矩阵代替，省纹理但表达能力有限 |

## 5. 锐化

### 5.1 Unsharp Mask

$$
I' = I + amount \cdot (I - G_{\sigma} * I)
$$

- `I - blur` 是高频细节；乘系数加回原图。
- `amount` 过大产生白边/黑边（halo），尤其在强边缘。
- 可加阈值：只增强超过阈值的细节，避免放大噪声。

### 5.2 CAS（Contrast Adaptive Sharpening）

AMD 的 CAS 根据局部对比度自适应调整锐化强度：

- 低对比区域多锐化（恢复细节），高对比边缘少锐化（抑制 halo）。
- 一次 3×3 采样，成本低，适合游戏后处理。
- 常与降采样/超分搭配（如 FSR 的 RCAS）。

### 5.3 与分辨率的关系

- 在**显示分辨率**做锐化，不要在低分辨率中间目标上做后再上采样，否则锐化的是插值伪影。
- 视频播放链路中，若解码输出 1080p、显示 4K，锐化应放在上采样之后（或使用带锐化的超分）。

## 6. 降噪

### 6.1 空间域

| 算法 | 原理 | 质量 | 成本 |
|---|---|---|---|
| 高斯 | 邻域加权平均 | 糊 | 低 |
| 双边 | 保边平均 | 中 | 中 |
| NLM | 相似块加权平均 | 高 | 很高 |
| BM3D | 块匹配 + 协同滤波 | 很高 | 极高（非实时） |

NLM 的权重是"块相似度"而非"像素差"：

$$
w(p,q) = \exp\left(-\frac{\|P(p)-P(q)\|^2}{h^2}\right)
$$

块匹配让它在纹理区域也能降噪，但搜索窗口大，实时通常要限制搜索范围或降采样。

### 6.2 时域与时空域

| 方法 | 关键输入 | 风险 |
|---|---|---|
| TAA | 深度、运动矢量、历史帧 | 拖影、ghosting |
| 时域降噪（TNR） | 运动矢量、亮度差 | 运动物体残影 |
| 时空联合 | 空间滤波 + 时域累积 | 实现复杂，需 clamp |

时域降噪的核心是**历史帧重用 + 有效性判断**：

```glsl
vec2 prevUV = uv - motionVector;
vec4 history = texture(u_history, prevUV);
float valid = ...;  // 深度/法线/颜色差异 + 屏幕边界
color = mix(current, history, valid * blendFactor);
```

- 运动矢量必须包含相机运动与物体运动，缺一不可。
- 遮挡/新暴露区域要拒绝历史帧，否则出现"鬼影"。
- 时域累积会放大 banding，需要 dither。

### 6.3 选择建议

| 场景 | 推荐 |
|---|---|
| 视频播放实时降噪 | 轻量空间滤波 + 时域（可选） |
| 光追/路径追踪 | 时空降噪（SVGF/BM3D 类） |
| 相机预览 | 平台 ISP 已做，应用层避免重复 |
| 离线导出 | BM3D/NLM，质量优先 |

## 7. Debanding 与 Dithering

### 7.1 色带成因

8bit 量化在平滑渐变上产生可见台阶。即使在 sRGB 空间，暗部相邻码值对应的线性亮度差也很小，但人眼对暗部梯度敏感，因此 banding 常出现在天空、雾、暗部渐变。

### 7.2 解决手段

| 方法 | 说明 |
|---|---|
| 提高位深 | 10bit 输出/中间缓冲，最直接 |
| 加噪（dither） | 在量化前加小幅噪声，把台阶打散 |
| 蓝噪声 | 噪声频谱在高频，视觉上更"干净" |
| 误差扩散 | 把量化误差传给邻像素，质量高但难并行 |
| 梯度感知抖动 | 按局部梯度调整噪声幅度 |

```glsl
// 有序抖动（4x4 Bayer）
float bayer = bayer4x4(gl_FragCoord.xy);
color += (bayer - 0.5) / 255.0;
```

- 抖动的幅度约为 1 个量化步长；太大变成噪点，太小无法打散色带。
- 在 sRGB 编码后、写入 8bit 附件前加；顺序错了无效。
- 视频链路中，如果源是 10bit、显示是 8bit，tone mapping 后必须 dither。

## 8. 光流与插帧

### 8.1 光流估计

| 方法 | 原理 | 实时性 |
|---|---|---|
| 块匹配 | 在搜索窗内找最相似的块 | 可实时（硬件/优化） |
| Lucas-Kanade | 局部亮度恒定 + 小运动 | 稀疏点，快 |
| Farneback | 多项式展开，稠密光流 | 中等 |
| 深度学习（FlowNet/RIFE） | 网络直接回归 | 需 NPU/GPU 加速 |

### 8.2 插帧

给定 `t` 时刻的前后帧 `I0/I1` 与光流 `F0→1`：

```glsl
vec2 uv0 = uv + t * flow0;
vec2 uv1 = uv - (1.0 - t) * flow1;
vec3 color = mix(texture(u_prev, uv0).rgb, texture(u_next, uv1).rgb, t);
```

工程难点：

- **遮挡**：一个像素在前帧可见、后帧不可见，双向光流不一致，需要 occlusion mask。
- **大运动**：搜索范围/网络感受野不够，产生撕裂。
- **重复纹理**：块匹配出现多解，光流跳变。
- **字幕/UI**：不应插帧，需区域保护。

### 8.3 视频播放中的取舍

- 24→60/120 FPS 的 MEMC 常见于电视，移动端因功耗与伪影较少默认开启。
- 插帧会引入 1 帧以上延迟，交互场景（云游戏、车载倒车影像）通常禁用。
- 倒车影像对延迟极敏感，宁可不插帧也不能延迟 ⚠️。

## 9. 超分与 NPU 加速

### 9.1 空间超分

| 方法 | 说明 | 成本 |
|---|---|---|
| 双线性/双三次 | 传统插值 | 极低 |
| Lanczos | 更锐利，有振铃 | 低 |
| FSR 1/2 | 空间/时域超分，游戏常用 | 中 |
| CNN 超分（ESPCN/EDSR） | 学习式，质量高 | 高，需 NPU |
| GAN 超分 | 感知质量高，可能生成伪细节 | 很高 |

### 9.2 NPU 路径

```
解码输出 (GPU/NPU 可访问 buffer)
   → 预处理（归一化/色彩转换）
   → NPU 推理（NCNN/MNN/TFLite）
   → 后处理（去块/锐化）
   → GPU 合成
```

- 关键是**零拷贝**：解码器输出直接作为 NPU 输入，避免 CPU 往返。见 [跨平台与高性能架构 §4](../04-跨平台与高性能架构/跨平台与高性能架构.md#4-ai-推理与图形渲染零拷贝互操作)。
- NPU 的输入格式（NHWC/NCHW、量化 int8）与 GPU 纹理布局不同，可能需要一次转换。
- 超分的收益在低分辨率源上明显；对已高质量源可能只是"加锐化"。

### 9.3 质量与延迟

- 超分通常增加 1–2 帧延迟，车载倒车/云游戏需评估。
- 生成式超分可能改变语义内容（车牌、文字），功能安全场景禁用 ❗。

## 10. YUV 域 vs RGB 域处理

| 处理 | 建议域 | 原因 |
|---|---|---|
| 亮度降噪/锐化 | Y 域 | 避免放大色度噪声；色度人眼不敏感 |
| 色彩调整 | RGB 或 YUV | 取决于调整类型 |
| 缩放 | YUV（4:2:0 需注意色度对齐） | 省带宽，但色度上采样要正确 |
| 色调映射 | 线性 RGB | 需要线性光强 |
| 字幕/UI 叠加 | RGB | 避免色度子采样导致文字彩边 |

**色度子采样陷阱**：4:2:0 的 U/V 分辨率是 Y 的一半，直接对 Y 和 UV 用同一套 UV 坐标会错位半个/一个像素。缩放或滤镜时必须按平面分别处理。

## 11. 预算速查

以 1080p、60 FPS、移动端中高端 GPU 为例（数量级参考，`[经验值]` ⚠️）：

| 操作 | 相对成本 | 备注 |
|---|---|---|
| 逐像素 LUT/调色 | 1× | 1 次采样 |
| 3×3 卷积 | 2–3× | 纹理缓存友好 |
| 可分离高斯 9×9 | 4–6× | 两个 pass |
| 全屏双边 9×9 | 20×+ | 81 次采样，不可分离 |
| 降采样到 1/4 再模糊 | 0.25× + | 感受野大、带宽低 |
| 时域降噪 | 2× + 历史帧带宽 | 需运动矢量 |
| NPU 超分 | 取决于模型 | 延迟与功耗需实测 |

**优化优先级**：

1. 降分辨率做低频操作（Bloom、模糊、AO）。
2. 合并 pass（能在一个 shader 里算完就不要拆）。
3. 用可分离核替代 2D 核。
4. 减少中间格式位宽（16F → 11/10F → 8）。
5. 避免全屏 `discard` 和随机采样。

## 12. 自测问答

**Q1：为什么高斯卷积要拆成两个 pass？**
二维核可分离，`N×N` 采样降到 `2N`；代价是多一张中间纹理与一次读写，但通常仍远低于省下的采样。

**Q2：双边滤波为什么不能直接分离？**
值域权重依赖邻域像素值，水平 pass 后的结果改变了垂直 pass 的权重要素，严格分离不成立，只能近似。

**Q3：引导滤波为什么能做到 O(1)？**
核心是盒滤波，盒滤波可用积分图/滑动窗口实现与半径无关；整个算法是若干次盒滤波的组合。

**Q4：3D LUT 的三线性插值和四面体插值差在哪？**
三线性 8 次采样、沿立方体对角混合；四面体按输入点所在四面体选 4 个顶点，采样更少且对非线性映射更准确，色偏更小。

**Q5：Unsharp mask 为什么会产生白边？**
在强边缘处 `I - blur` 有过冲，乘系数后超过原图范围，形成 halo。解决：阈值、CAS 的自适应、或限制 overshoot。

**Q6：时域降噪的鬼影怎么来的？**
历史帧对应像素已经不属于同一物体（遮挡、运动、光照变化），但仍被混合进来。解决：运动矢量、深度/法线校验、颜色 clamp、失效区域重置。

**Q7：8bit 管线为什么必须 dither？**
量化步长固定，平滑渐变会出现台阶；加 1 LSB 量级的噪声把台阶打散成高频噪点，人眼更不易察觉。

**Q8：插帧为什么会撕裂？**
前后帧光流不一致（遮挡/大运动/重复纹理），前后向采样落在不同物体上。需要 occlusion mask 与光流一致性校验。

**Q9：超分能不能替代高分辨率渲染？**
不能完全替代。超分恢复的是"统计上合理"的细节，对文字、细线、车牌等语义敏感内容可能生成错误；渲染端仍需保证足够采样。

**Q10：移动端图像算法最先优化什么？**
先降 pass 数和分辨率，再谈 ALU。多数后处理是带宽瓶颈，不是算力瓶颈；能用 1/4 分辨率做的绝不全屏做。

> **一句话总结**：GPU 图像算法的成本约等于"pass 数 × 分辨率 × 带宽 × 采样数"；先做减法和降采样，再考虑更聪明的核。
