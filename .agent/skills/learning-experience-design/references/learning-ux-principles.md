# 学习体验原理（为什么这样设计）

> 本文回答"为什么"。具体的 token 值、字号、色板见 `design-system.md`；页面结构见 `learning-page-archetypes.md`。本文不复述那些规范。

## 1. 网站的目标不是渲染 Markdown
Render_Notes 的学习站不是"把知识库发布出来"，而是帮助学习者：发现知识 → 理解概念 → 建立联系 → 按认知顺序学习 → 理解复杂原理 → 通过图表看懂机制 → 用交互实验验证理解 → 形成长期记忆。任何设计决定都要能回答"它帮助了上述哪一步"，回答不上来的装饰应删掉。

## 2. 认知负荷：把有限的工作记忆花在核心概念上
- **内在负荷**：概念本身的难度。不能消除，只能顺序化——前置知识先讲透（对应 `learning-interaction-patterns.md` 的前置检查）。
- **外在负荷**：由糟糕呈现带来的额外负担。要最小化：一致的标题层级、稳定的导航、不用读者猜的术语入口、代码块不横向溢出。
- **相关负荷**：用于建立理解的思考。要最大化：因果推导、数值算例、对比表、让用户预测结果的实验。
- 判据：若一个视觉元素增加了外在负荷却没有提升相关负荷，它是负贡献。

## 3. 检索练习比重复阅读更有效
每个学习单元要有"合上页面也能回忆"的钩子：checkpoint 提问、quiz、让我先预测再揭晓的实验。学习站里的自测不是附属品，是理解闭环的一部分——对应旧 `interaction-patterns.md` 中的组件，但这里给出原理：主动检索强化记忆痕迹，被动重读制造熟悉感错觉。

## 4. 渐进披露：先给心智模型，再给细节
先直觉理解（它大概是什么、为什么存在），再概念建立，再因果推导，最后才是公式与工程细节。这与 Render_Notes 教材的"问题引入 → 前置 → 直观 → 概念 → 推导 → 数学工程 → 实践 → 迁移 → 承接"九段结构一致（`research-to-learning` 的 lesson-quality-standard）。页面设计要支持这条线：不要让公式在读者建立直觉之前出现。

## 5. 理解闭环：一篇教材必须自洽
读者不该"去看另一篇文档才知道核心原理"。每篇教材在自己的页面内完成：问题 → 直觉 → 机制 → 验证 → 小结 → 承接。跨文档链接用于延伸，不承担解释核心机制的责任。这是 P2 相对当前站点最需要改进的地方。

## 6. 可视化服务于因果，不服务于好看
图的作用是让看不见的机制变得可见（数据流、状态迁移、坐标变换、同步时序）。选择哪种图取决于知识的因果结构，不取决于模板库里有什么。反对：每篇文章塞满同质卡片、装饰性图标、无信息量的时间轴。详见 `educational-visualization.md`。

## 7. 一致性降低学习成本
相同的概念在全站用同样的术语、同样的视觉标识、同样的链接入口。术语定义唯一来源是 `tools/glossary.json`（项目规则），不在各处重写定义。一致性不是为了"整齐"，是为了让读者把注意力放在知识差异上，而不是界面差异上。

## 8. 与 Floor/Reflex/Finish 的关系
本文的原理主要支撑 **Reflex 与 Finish** 层的判断（"这样做是否真的帮助理解"）；**Floor 层是硬约束**，其判定标准见 `accessibility-and-responsive.md` 与 `ux-review-checklist.md`，不因审美或"设计原理"而豁免。
