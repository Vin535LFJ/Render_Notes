## 1. Question

`stash@{0}` 中三处用户本地改动应继续保留、pop 恢复、drop 丢弃，还是先导出 diff 存档后再决定？

## 2. Context（最小必要背景）

- **背景**：`stash@{0}` 保存了三处用户本地改动（README / archive / 学习路径指南）。是否恢复、如何恢复属用户自己的决定；AI 在准备材料时**只读查看了 diff，未执行任何 pop/drop/apply**。
- **影响范围**：stash 本身、`00-导航与索引/学习路径指南.md`、`archive/**`（受保护）、当前工作区未提交改动。
- **成本**：A 近零；B 需冲突处理 + 门禁复跑；C 不可逆；D 一次只读导出。
- **回滚**：A/D 可逆；B 恢复后可再 stash；C **不可回滚**。
- **不作为的后果**：stash 继续保留，无实质损失；用户改动随时可恢复。
- **证据（路径 / 行号 / 命令输出 / commit / ADR）**：
  - `reviews/DECISION_REQUIRED.md:90-94`：选项为 pop / drop / 继续保留（原建议"继续保留"）；裁决栏空白。
  - `git stash list`（2026-11-19 只读执行）：`stash@{0}: On master: sync-pull: 暂存README/archive/学习路径指南3处本地改动`。
  - `git stash show -p stash@{0}`（只读）关键结论：
    - 涉及 `00-导航与索引/学习路径指南.md` 等文件；
    - 改动内容为把推荐阅读链接从 `01-基础理论/音视频基础理论.md` 改为 `../01-基础理论/音视频基础理论.md`（加 `../` 相对路径前缀），涉及全部 20 条推荐阅读链接；
    - 属于**链接路径修正**性质，不是内容重写。
  - 当前工作区已有 37+ 项未提交增量；stash 与工作区是两条独立状态线。

## 3. Options and tradeoffs

| 选项 | 收益（优点） | 代价 / 风险（缺点） | 前置条件 / 成本 |
|---|---|---|---|
| A · 继续保留 stash 不动（推荐） | 零风险，保留用户改动 | stash 长期悬挂 | 近零 |
| B · `git stash pop` 恢复到工作区 | 恢复用户意图 | 与大量未提交改动冲突风险；触及受保护的 `archive/**` 相关路径需格外谨慎 | 冲突处理 + 门禁复跑 |
| C · `git stash drop` 丢弃 | 清理状态 | **不可逆**，丢失用户改动 | 不可回滚 |
| D · 只查看、导出 diff 存档后再决定 | 留档后决策 | 仍需后续决定 | 一次只读导出 |

**参考建议（非裁决）**：选 **A 继续保留**——当前工作区改动面大，pop 有冲突风险且触及受保护的 `archive/**` 相关路径；drop 不可逆。待本轮增量稳定后，由用户自己决定是否单独恢复。AI 未执行任何 stash 写操作。
