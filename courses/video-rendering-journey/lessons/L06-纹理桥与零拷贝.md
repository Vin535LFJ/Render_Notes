# 纹理桥与零拷贝

> **本章回答**：解码出来的像素帧怎么变成 GPU 能采样的纹理？"零拷贝"真的一个字节都不拷吗？

## 1. 从一个问题开始

硬解输出的是 YUV 像素，GPU 着色器要采样的是纹理。中间要跨一道桥。朴素做法是 CPU 把像素读出来、再 `glTexImage2D` 上传——几兆字节逐帧搬，总线带宽和发热都很重。有没有办法不搬？

## 2. 学习前提

- 上一章的帧与时间戳；L05 的硬解 ownership 概念。
- 术语 OES：**GL_TEXTURE_EXTERNAL_OES** 是 OpenGL ES 中用于外部图像采样的纹理类型（断言 `V04`）。

## 3. 直观认识

把像素想象成一批货。零拷贝不是"不运货"，而是"不让 CPU 亲手一箱箱搬"——让解码器、GPU、合成器共享同一个仓库（缓冲区）的钥匙（文件描述符），谁要用自己去取。断言 `V05` 明确：零拷贝是"尽量减少拷贝"而非绝对 0 拷贝。

## 4. 一步一步理解原理

### 4.1 共享缓冲区

硬解把 YUV 写进 Gralloc/DMA-BUF 缓冲，应用层调用 `SurfaceTexture.updateTexImage()` 把最新帧绑定为 OES 外部纹理，并用 `SurfaceTexture.getTransformMatrix()` 取出纹理坐标变换矩阵矫正视频自带的旋转角。CPU 只传句柄不搬像素——这就是近零拷贝的实质（断言 `V05`：`C02` Surface 直出零拷贝、`P02` 全链路零拷贝⚠️有限定条件）；详见[解码与播放链路 §7.1 / §7.3](../../../02-解码与播放链路/解码与播放链路.md)。

### 4.2 OES → 第一道转换 Shader → FBO → 2D 纹理

OES 纹理采样参数受限，不能直接进普通 Effect Pass。工业做法（源文档 §7.2 / §7.4，✅已验证）是通过 FBO 离屏渲染，由**第一道转换 Shader** 处理旋转矩阵与 YUV→RGB 色彩空间转换，输出标准 `GL_TEXTURE_2D` 后再进特效链——源文档称它为"第一道转换 Shader"，不是某个"OES Input Pass"。色彩空间转换原理见[色彩管理与采样滤波](../../../03-图形与GPU工程/色彩管理与采样滤波.md)。

> 历史上这里曾误引"源文档 §7.3"，但 §7.3 讲的是零拷贝的真实含义；转换机制在 §7.2 与 §7.4，已更正。

特效链加工完成后的标准 2D 纹理分两路：预览渲染到 TextureView/GLSurfaceView 上屏，导出渲染到编码器 Input Surface 硬编。为保证剪辑"所见即所得"，两条管线**共享同一套 OpenGL 特效 Shader 代码**（[解码与播放链路 §8](../../../02-解码与播放链路/解码与播放链路.md)）——这是 Shader 复用，不是共享 RenderGraph（RenderGraph 是 L11 的工程架构议题）。

### 4.3 两种平台的通路差异

PC 独显有独立显存，系统内存 → 显存要跨 PCIe、由 DMA 搬移；移动 SoC 无 PCIe，CPU/GPU 共享同一块 DRAM。这就是很多人被 DRAM/DMA/PCIe 绕晕的根源——断言 `E02`；桥梁见[概念引入说明 §数据通路](../../../00-导航与索引/概念引入说明.md#1-数据通路dram-dma-pcie-各是什么)。

## 5. 数学原理 / 数据形态

零拷贝与否看"像素是否经过 CPU 搬移"：软解路径是 `码流 → 主存 → CPU 解码 → 主存 → 总线拷贝 → 显存`；硬解共享是 `码流 → VPU → Gralloc 缓冲 → GPU 采样`，CPU 不碰像素。

## 6. 工程应用与常见错误

- **误区**："零拷贝 = 零成本。" 驱动或格式转换仍可能触发隐式拷贝（`V05` 条件）。
- **误区**："Surface 直出一定零拷贝。" 需绑定 Surface 给解码器（`C02`）。
- **误区**："手机也有 PCIe 传纹理。" 移动 SoC 走共享内存，没有 PCIe（`E02`）。
