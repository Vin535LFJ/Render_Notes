# Educational Visualization（教学可视化）

> 图的目的必须是帮助理解，不是装饰。结合知识类型选择，不能默认每篇文章塞卡片和图表。

## 选择矩阵（知识类型 → 表达方式）

| 知识类型 | 推荐表达 | 例子（Render_Notes 实际内容） |
|---|---|---|
| 组成/分类 | 结构示意图、层级图 | 坐标空间链、管线阶段 |
| 流动/处理 | 数据流图 | 一帧画面从解码到上屏、MVP 数据流 |
| 时序/演进 | 时间轴 | 音视频同步 Δt、seek 追赶过程 |
| 因果 | 因果关系图 | 为什么需要投影空间 |
| 数学机制 | 分步推导 + 数值算例 | 透视除法、NDC 变换 |
| 方案对比 | 对比表 | OpenGL vs Vulkan NDC、DTS vs PTS |
| 状态流转 | 状态机 | ExoPlayer 状态、RenderGraph aliasing |
| 抽象→具体 | 前后对照、交互实验 | 零拷贝软解/硬解路径对比 |

## 设计规则
1. **一图一义**：每张图说明一个关系；塞太多关系就拆图。
2. ** annotate**：关键节点/边给文字说明；轴上带单位。
3. **主题适配**：明暗两套配色；线条/箭头对比度足够。
4. **可访问**：图下方或 alt 给文字等价描述；不只靠颜色区分。
5. **可放大**：Mermaid 图沿用现有 lightbox；复杂图允许点击放大。
6. **可操作优先**：能用交互实验表达的，比静态图更能验证理解（见 `interaction-patterns.md`）。

## 反模式
- 每篇文章开头放一张无关的概念图凑数。
- 用渐变/发光让图"好看"但难读。
- 图例缺失、节点无标签。
- 深色主题下图变成一片糊（对比未适配）。
- 静态图表达本该动态的机制（同步、状态流转）。

## 落地
- Mermaid 用项目现有渲染；流程图/时序图优先 Mermaid 语法（可维护）。
- 复杂定制图放 `web/assets/` 并由构建脚本引用；不在正文内联大段 SVG 破坏可读性。
- 每张图配一句"读图指引"：先看哪里、箭头代表什么、结论是什么。
