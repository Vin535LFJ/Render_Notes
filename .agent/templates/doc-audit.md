# 文档审计（Document Audit）

> 一次性审计清单：目标是"可审计、可恢复、可交接、与最新代码一致"。
> 禁止凭感觉判定过时；每条结论必须有依据。

## 0. 预检

- 读适配入口 / 宪法（AGENTS.md 等），确认仓库约定与基准仓：
- git status（tracked / untracked / 用户未提交改动）：
- 与用户确认范围（含禁区）：
- Owner Agent / 允许修改 / 禁止修改：

## 1. 盘点

| 文档 | 路径 | 行数 | tracked | 被谁引用 | 最后更新 |
|---|---|---|---|---|---|

（多分区可并行盘点，但整合写入只有一个 Owner Agent。）

## 2. 失效判定（每条必须给依据）

| 文档 | verdict（活跃 / 过时保留 / 归档 / 删除候选） | 依据（commit / ADR / 取代者路径 / 实测输出） | 处理动作 |
|---|---|---|---|

无依据 → 标"待确认"，不执行归档或删除。

## 3. 收敛唯一行动入口

- 当前自称入口的文档清单：
- 保留的唯一入口（路径）：
- 其余处理（superseded 横幅 / 归档 / 退役存根）：
- 所有活导航指针是否已统一（grep 验证）：

## 4. 现场重测数字

| 数字项 | 旧文档值 | 实测命令 | 实测值 | 处理 |
|---|---|---|---|---|

（测试数、commit tip、文档 / 术语 / 断言计数、关键文件行数；以最新代码为准，不抄旧值。）

## 5. 链接与索引

- 断链扫描命令与输出：
- 逐条确认真伪（防假断链，已指向正确归档位置的不要改）：
- 批次归档 README / 总索引 / 主路由是否更新：

## 6. 归档与删除（安全）

- 归档路径（`archive/<批次日期>/`）：
- 删除候选清单（先列给用户确认）：
- 删除方式（回收站 + 追溯 README）：
- 归档优先；不对活文档使用 shell 强删。

## 7. 状态产出与交接

- CURRENT_STATE / ROADMAP（或项目等价状态文档）更新点：
- 遗留决策三组：可立即执行 / 需用户拍板 / 代码侧：
- 自包含交接提示词：
- 最终验证（链接 / 索引覆盖 / git 噪声）：

> 本项目落点：实例放 `.agent/changes/<change-id>/doc-audit.md`；断链扫描沿用 `tools/validate_site.py`，不另建脚本。
