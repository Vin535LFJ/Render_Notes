# 坐标变换与 MVP

> **本章回答**：同一个三角形，为什么经过几次矩阵乘法就能有透视、有远近，还能正确落到屏幕像素上？

## 1. 从一个问题开始

把一张纸上的三角形贴到三维场景里，转个角度、离远一点——它在屏幕上会变小、变形。GPU 怎么做到的？不是"猜"，而是几个坐标空间之间的一串矩阵乘法。任何一个空间缺失，画面就会错。

## 2. 学习前提

- L08 的管线；基础代数（矩阵乘法）。
- 术语 MVP = Model / View / Projection，三个矩阵的组合。

## 3. 直观认识

想象给一个物体拍照：先把它摆到房间里（模型→世界），再架好相机（世界→观察），再决定用广角还是长焦（观察→裁剪），最后投影到相片（裁剪→屏幕）。每一步对应一个空间与一个矩阵。

## 4. 一步一步理解原理

### 4.1 六个空间

模型 / 世界 / 观察 / 裁剪 / NDC / 屏幕，各自的单位、原点与用途见[3D变换与坐标空间 §坐标空间链](../../../07-3D渲染与算法实现/3D变换与坐标空间.md)。

### 4.2 为什么需要投影空间

没有投影空间，远处的物体不会变小——正交投影能画对位置却没有透视感。投影矩阵把深度信息写进 w，透视除法由 GPU 固定管线在 clip→NDC 阶段完成（断言 `V19`，源自[3D变换与坐标空间 §4 投影矩阵 / §1.2](../../../07-3D渲染与算法实现/3D变换与坐标空间.md)）。详见源文档 §投影矩阵。

### 4.3 NDC 与 Y-flip

NDC 的跨 API 差异要按表记，而不是笼统说"Y 轴可能相反"（断言 `V20`，源自[3D变换与坐标空间 §5 NDC 与视口差异表](../../../07-3D渲染与算法实现/3D变换与坐标空间.md#5-ndc-与视口跨-api-差异表)）：

| API | NDC x/y | NDC z | NDC Y 方向 | 帧缓冲原点 |
|---|---|---|---|---|
| OpenGL / GLES | `[-1,1]` | `[-1,1]` | 向上 | 左下 |
| Vulkan | `[-1,1]` | `[0,1]` | **向下** | 左上 |

这是默认约定：Vulkan 的 Y 方向可用**负视口高度**翻转，正面绕序可由 `frontFace` 配置。跨 API 移植时以"最终像素落在哪"为准，不要只背表——这是最高频的事故源。

## 5. 数学原理 / 数据形态

列向量约定下从右到左依次乘：`gl_Position = P · V · M · vec4(pos, 1)`（断言 `V18`，源自[3D变换与坐标空间 §1.2 / §2.1](../../../07-3D渲染与算法实现/3D变换与坐标空间.md)）。矩阵乘法的顺序不可交换——先 M 再 V 再 P，与直觉的"先投影"正好相反，因为矩阵作用在列向量的右侧。HLSL 行主序约定下顺序写法相反（`mul(v, M)`）。

坐标空间链的完整职责分解见断言 `V17`：model（摆放）→ world → eye（相机）→ clip（投影/裁剪）→ NDC（透视除法后归一化）→ window（视口落屏），每步解决一个独立问题。

## 6. 工程应用与常见错误

- **误区**："MVP 只有一个矩阵。" 它是三次变换的组合。
- **误区**："透视除法在顶点着色器手动做。" 错——必须在 clip→NDC 由固定管线完成（`V19`）。手动除会破坏透视正确插值：硬件按 `attr / w` 插值、在片元乘回 `w`，提前除掉 w 后 interpolation 变成屏幕空间线性，斜面上的纹理会扭曲。
- **误区**："OpenGL 和 Vulkan 的 NDC 一样。" 深度范围与 Y 方向默认都不同（`V20`）；Vulkan 可用负视口高度翻 Y、`frontFace` 改绕序。
