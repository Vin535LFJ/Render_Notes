## 1. 坐标空间与变换链

### 1.1 五个空间

```
模型空间 (Local/Object)
   │  Model Matrix (M)
   ▼
世界空间 (World)
   │  View Matrix (V)
   ▼
观察空间 (View/Camera/Eye)
   │  Projection Matrix (P)
   ▼
裁剪空间 (Clip)
   │  透视除法 (÷w)
   ▼
NDC
   │  视口变换 (Viewport)
   ▼
屏幕空间 (Screen)
```

**一句话**：`gl_Position = P * V * M * vec4(localPos, 1.0)`。

### 1.2 每个矩阵在干什么

| 矩阵 | 组成 | 常见错误 |
|---|---|---|
| **M（模型）** | 平移 × 旋转 × 缩放（顺序敏感） | 先缩放再旋转 vs 先旋转再缩放结果不同 |
| **V（视图）** | 相机世界变换的逆 | 用相机矩阵本身而不是逆矩阵 |
| **P（投影）** | 透视/正交，定义视锥与深度映射 | 近平面过小导致深度精度崩溃 |

**顺序规则**：GLSL 列主序下，`M = T * R * S` 表示"先缩放、再旋转、最后平移"（右乘先作用）。面试常问"为什么我的模型绕自身原点转，不是绕世界原点"——就是 M 的乘法顺序问题。

### 1.3 透视投影矩阵

标准 OpenGL 透视投影（右手系，看向 -Z，NDC 深度 [-1,1]）：

$$
P =
\begin{bmatrix}
\frac{f}{aspect} & 0 & 0 & 0 \\
0 & f & 0 & 0 \\
0 & 0 & \frac{near+far}{near-far} & \frac{2 \cdot near \cdot far}{near-far} \\
0 & 0 & -1 & 0
\end{bmatrix},
\quad f = \frac{1}{\tan(\frac{fovY}{2})}
$$

- 第 3 行第 4 列的 `-1` 把 `-z` 写入 `w`，透视除法后产生近大远小。
- 深度非线性：大部分精度集中在近平面附近。**near 从 0.1 提到 1.0，远处精度可提升约 10 倍**。

### 1.4 NDC 与深度范围：三套约定

| API | NDC x/y | NDC z | 纹理/帧缓冲原点 | 裁剪空间 Y |
|---|---|---|---|---|
| OpenGL | [-1, 1] | **[-1, 1]** | 左下 | 向上 |
| Vulkan | [-1, 1] | **[0, 1]** | 左上 | 向下 |
| D3D | [-1, 1] | [0, 1] | 左上 | 向下 |
| WebGPU | [-1, 1] | [0, 1] | 左上 | 向下 |
| Metal | [-1, 1] | [0, 1] | 左上 | 向下 |

**移植要点**

1. GL → Vulkan/D3D：深度 `z_ndc' = (z_ndc + 1) / 2`，或直接改投影矩阵。
2. Y 翻转：可在投影矩阵乘一个 Y 缩放 -1，或在视口/UV 层处理。**不要两处都翻**，否则画面倒置。
3. 反向 Z（reversed-Z）在 D3D/Vulkan 上可大幅提升深度精度，GL 因裁剪范围限制较难使用。

### 1.5 视口变换

```
x_screen = (x_ndc * 0.5 + 0.5) * viewportWidth  + viewportX
y_screen = (y_ndc * 0.5 + 0.5) * viewportHeight + viewportY   // GL：原点左下
z_depth  = z_ndc * 0.5 + 0.5                                   // GL：映射到 [0,1]
```

FBO 渲染时 `glViewport` 必须与附件尺寸一致，这是"画面只渲染左下角/拉伸"的头号原因。

## 2. 相机与投影类型

### 2.1 透视 vs 正交

| 维度 | 透视 | 正交 |
|---|---|---|
| 平行线 | 汇聚于灭点 | 保持平行 |
| 尺寸 | 近大远小 | 与距离无关 |
| 用途 | 3D 车模、环视、游戏 | UI、2D、工程视图、阴影（方向光） |
| 深度 | 非线性 | 线性 |

### 2.2 相机参数与手感

- **FOV**：垂直视场角。车载 HMI 常用 45°–60°；FOV 过大边缘畸变明显。
- **aspect**：必须与视口一致，否则画面拉伸。
- **near/far**：在满足需求的前提下尽量收紧，保护深度精度。
- **曝光**：物理相机用 EV100；实时渲染常直接调 tone mapping 曝光。

### 2.3 视图矩阵构造

```cpp
// lookAt：eye, center, up
vec3 f = normalize(center - eye);   // forward
vec3 s = normalize(cross(f, up));   // right
vec3 u = cross(s, f);               // true up
mat4 V = mat4(
    vec4(s.x, u.x, -f.x, 0.0),
    vec4(s.y, u.y, -f.y, 0.0),
    vec4(s.z, u.z, -f.z, 0.0),
    vec4(-dot(s, eye), -dot(u, eye), dot(f, eye), 1.0)
);
```

注意：GL 相机看向 **-Z**，所以第三行是 `-f`。

## 3. 法线与切线

### 3.1 法线变换为什么不能用模型矩阵

法线是**余切向量**，在非均匀缩放下必须用 **模型矩阵左上 3×3 的逆转置**：

```glsl
mat3 normalMatrix = transpose(inverse(mat3(model)));
vec3 N = normalize(normalMatrix * a_normal);
```

**推导直觉**：切线沿表面方向变换用 M；法线必须保持与切线垂直，即 `(M·T)·(N') = 0`，解得 `N' = (M⁻¹)ᵀ·N`。

- 均匀缩放时逆转置 ∝ M，可直接用 `mat3(model)`（但仍需归一化）。
- 镜像（负缩放）会翻转手性，需要翻转法线或调整正面朝向。

### 3.2 切线空间与 TBN

法线贴图存储的是**切线空间**法线，需要 TBN 矩阵转到世界空间：

```glsl
vec3 N = normalize(v_normalWS);
vec3 T = normalize(v_tangentWS - N * dot(N, v_tangentWS)); // 正交化
vec3 B = cross(N, T) * v_tangentSign;                       // 手性
mat3 TBN = mat3(T, B, N);
vec3 n = normalize(TBN * (texture(u_normalMap, uv).xyz * 2.0 - 1.0));
```

**要点**

- 切线必须**正交化**（Gram-Schmidt），否则法线贴图会出现扭曲。
- `v_tangentSign`（±1）由 UV 手性决定，glTF 用 `TANGENT.w` 存储。
- 没有切线属性时可用屏幕空间导数现算（`dFdx/dFdy`），质量较差但省内存。
- MikkTSpace 是业界统一的切线生成标准，Unity/UE/Blender 都支持，跨 DCC 一致性靠它。

### 3.3 硬边与平滑

- 一个顶点只有**一组**法线/UV；硬边需要**复制顶点**（位置相同、法线不同）。
- 因此"顶点数"不等于"几何点数"，导入时 split normals 会增加顶点数。
- 平滑组（smoothing group）本质就是导入期的顶点分裂规则。

## 4. 光照模型：从 Lambert 到 PBR

### 4.1 三档模型

| 模型 | 公式核心 | 特点 | 用途 |
|---|---|---|---|
| **Lambert** | `diffuse = max(N·L, 0)` | 只有漫反射，无高光 | 低成本、风格化 |
| **Phong** | `spec = pow(max(R·V,0), shininess)` | 反射向量 R 计算贵 | 传统管线 |
| **Blinn-Phong** | `spec = pow(max(N·H,0), shininess)`，`H=normalize(L+V)` | 半程向量，便宜且更柔和 | 移动端常用 |
| **PBR（GGX）** | 微表面 BRDF | 能量守恒、物理一致 | 车漆、金属、玻璃 |

### 4.2 渲染方程（简化）

$$
L_o = \int_{\Omega} f_r(l, v) \, L_i(l) \, (n \cdot l) \, dl
$$

实时渲染把它离散为"直接光 + IBL 环境光"。

### 4.3 微表面 BRDF

$$
f_r = \frac{D(h) \, F(v,h) \, G(l,v)}{4 (n\cdot l)(n\cdot v)}
$$

| 项 | 含义 | 常用实现 |
|---|---|---|
| **D** | 法线分布 | GGX / Trowbridge-Reitz |
| **F** | 菲涅尔 | Schlick 近似 `F0 + (1-F0)(1-v·h)^5` |
| **G** | 几何遮蔽 | Smith + Schlick-GGX |

**GGX 分布**：

$$
D_{GGX}(h) = \frac{\alpha^2}{\pi ((n\cdot h)^2(\alpha^2 - 1) + 1)^2}, \quad \alpha = roughness^2
$$

**金属度工作流**

- `F0 = mix(vec3(0.04), albedo, metallic)`
- 漫反射 `kd = (1 - F) * (1 - metallic)`
- 金属没有漫反射；非金属 F0 约 0.04。

### 4.4 能量守恒与常见错误

- 漫反射 + 镜面反射之和不能超过入射能量；漏乘 `(1-F)` 会"越打光越亮"。
- `roughness` 不能为 0（除零/高光变成单像素噪点），一般 clamp 到 0.04。
- 法线未归一化、粗糙度反向（roughness vs smoothness）、金属度贴图通道搞错是三大高频 bug。

### 4.5 IBL（基于图像的光照）

| 步骤 | 内容 |
|---|---|
| 1 | 环境贴图 → 漫反射 irradiance map（卷积） |
| 2 | 环境贴图 → 镜面 prefiltered map（按 roughness 分级） |
| 3 | BRDF LUT（split-sum 近似） |
| 4 | 运行时：`specular = prefiltered(R, roughness) * (F0 * brdf.x + brdf.y)` |

车载车模的"展厅质感"高度依赖 IBL；只有直接光会显得塑料。

## 5. 阴影

### 5.1 Shadow Map 基本流程

1. 从光源视角渲染深度到深度纹理（`DEPTH_COMPONENT16/24`）。
2. 主 Pass 中把世界坐标变换到光源裁剪空间，采样深度比较。
3. 比较时加 bias 避免自阴影（shadow acne）。

```glsl
float shadow(vec4 lightSpacePos, float ndotl) {
    vec3 proj = lightSpacePos.xyz / lightSpacePos.w * 0.5 + 0.5;
    if (proj.z > 1.0 || any(lessThan(proj.xy, vec2(0.0))) || any(greaterThan(proj.xy, vec2(1.0))))
        return 0.0;
    float bias = max(0.05 * (1.0 - ndotl), 0.005);
    float d = texture(u_shadowMap, proj.xy).r;
    return proj.z - bias > d ? 1.0 : 0.0;
}
```

### 5.2 常见瑕疵与对策

| 瑕疵 | 原因 | 对策 |
|---|---|---|
| Shadow acne | 深度精度/斜率 | slope-scaled bias、normal offset |
| Peter-panning | bias 过大 | 减小 bias，用 normal offset |
| 锯齿 | 分辨率不足 | PCF、PCSS、更高分辨率、CSM |
| 远处稀疏 | 单张图覆盖范围大 | **CSM（级联阴影）** |
| 漏光 | 背面深度 | 双面渲染阴影、法线偏移 |

### 5.3 PCF

```glsl
float pcf(vec2 uv, float compare, vec2 texel) {
    float sum = 0.0;
    for (int x = -1; x <= 1; ++x)
        for (int y = -1; y <= 1; ++y)
            sum += step(compare, texture(u_shadowMap, uv + vec2(x, y) * texel).r);
    return sum / 9.0;
}
```

3×3 PCF 是 9 次采样；移动端可用 4-tap 旋转泊松盘近似。

### 5.4 CSM（级联阴影）

- 把视锥按距离切成 2–4 段，每段一张 shadow map。
- 近处分辨率高、远处低，解决"一张图覆盖整个场景"的精度问题。
- 级联接缝处需要 blend，否则出现阴影突变。

### 5.5 其他阴影方案

| 方案 | 特点 | 适用 |
|---|---|---|
| Shadow Volume | 几何模板，精确硬阴影 | 老式、复杂场景成本高 |
| VSM | 存深度矩，可模糊 | 软阴影，但漏光 |
| Ray-traced shadow | 最真实 | 桌面/高端，车载少见 |
| 屏幕空间接触阴影（SSAO/SSCT） | 补足接触处 | 与 shadow map 互补 |

## 6. 渲染路径：Forward / Deferred / Forward+

### 6.1 对比

| 维度 | Forward | Deferred | Forward+ / Clustered |
|---|---|---|---|
| 光照计算 | 每个物体 × 每盏灯 | 屏幕每像素 × 每盏灯 | 每像素只算影响它的灯 |
| 带宽 | 低（直接写最终颜色） | 高（G-Buffer 多附件） | 中 |
| MSAA | 原生支持 | 困难（需额外处理） | 支持 |
| 透明物体 | 直接支持 | 需单独 Forward Pass | 直接支持 |
| 材质多样性 | 着色器变体多 | G-Buffer 格式受限 | 较灵活 |
| 移动端 | **主流** | 带宽吃不消 ⚠️ | 逐步普及 |

### 6.2 G-Buffer 典型布局

| 附件 | 内容 | 格式 |
|---|---|---|
| RT0 | albedo + metallic | RGBA8 |
| RT1 | normal（octahedral 编码） | RG16 |
| RT2 | roughness + AO + 其他 | RGBA8 |
| Depth | 深度/模板 | D24S8 |

移动端可用 **MRT + framebuffer fetch** 在一个 Pass 内完成着色，避免 G-Buffer 落主存。

### 6.3 透明与排序

- 不透明：从前到后（利用 Early-Z 减少 Overdraw）。
- 透明：从后到前（保证混合正确），并关闭深度写入（保留深度测试）。
- 半透明自相交无法用排序解决，需要 OIT（加权混合、深度剥离）。

### 6.4 后处理顺序（重要）

```
场景渲染（线性 HDR）
  → Bloom
  → 景深 / 运动模糊
  → 色调映射（HDR → LDR）
  → 颜色分级（LUT）
  → FXAA / TAA
  → UI 合成（通常在 sRGB 空间）
```

**为什么 tone mapping 在 bloom 之后**：bloom 需要 HDR 亮度信息；先映射会丢失高光。
**为什么 AA 在 tone mapping 之后（FXAA）**：在 LDR 上做边缘检测更稳定；TAA 则通常在线性空间。

## 7. 抗锯齿

| 方案 | 原理 | 成本 | 备注 |
|---|---|---|---|
| **SSAA** | 超采样后降采样 | 极高 | 质量基准 |
| **MSAA** | 每像素多采样覆盖/深度，着色一次 | 中高（带宽） | 几何边缘有效，着色锯齿无效 |
| **FXAA** | 后处理边缘检测 + 模糊 | 低 | 模糊细节，文字变糊 |
| **SMAA** | 形态学边缘 | 低中 | 比 FXAA 好 |
| **TAA** | 多帧抖动 + 历史重投影 | 中 | 需要运动向量，会拖影 |
| **DLSS/FSR** | 超分 + 时序 | 中 | 平台相关 |

车载 HMI 的文字/图标多，**FXAA 会让小字发糊**，常用 MSAA 或直接提高分辨率。

## 8. 色彩管线（3D 渲染必须懂）

### 8.1 线性工作流

```
sRGB 纹理 →(硬件 sRGB 解码)→ 线性空间 → 光照计算 → tone mapping → sRGB 编码 → 显示器
```

- 纹理若不是 sRGB 格式，采样得到的是"gamma 编码值"，直接参与光照会偏暗/偏亮。
- 帧缓冲若为 `GL_SRGB8_ALPHA8`，写入时硬件自动编码；否则需要手动 `pow(color, 1/2.2)`。
- **Alpha 永远不参与 gamma 编码**。

### 8.2 HDR 与色调映射

| 指标 | 说明 |
|---|---|
| PQ（ST2084） | HDR10 传输函数，绝对亮度映射 |
| HLG | 广播级 HDR，兼容 SDR |
| ACES | 电影级 tone mapping 曲线 |
| Reinhard | 简单，`c/(1+c)` |
| Filmic | 保留高光细节 |

车载屏幕亮度范围有限，HDR 主要用于高端座舱；普通屏仍以 SDR + 良好 tone mapping 为主。

### 8.3 视频与 3D 混合

视频帧通常是 **BT.709 limited range YUV**，3D 场景是线性 RGB。混合前必须：
1. YUV → RGB（矩阵 + range 展开）
2. gamma 解码到线性
3. 在线性空间合成
4. 统一 tone mapping + 编码输出

详见 [色彩管理与采样滤波](../../03-图形与GPU工程/色彩管理与采样滤波.md)。

## 9. 3D 几何原理（网格与数据）

### 9.1 网格的基本属性

| 属性 | 内容 | 备注 |
|---|---|---|
| position | vec3 | 必须 |
| normal | vec3 | 光照必需 |
| tangent | vec4 | 法线贴图必需（w 存手性） |
| uv0/uv1 | vec2 | 多套 UV 用于烘焙/细节 |
| color | vec4 | 顶点色，常用于 AO/风摆权重 |
| joints/weights | 4×u8/u16 + 4×f32 | 蒙皮 |

### 9.2 索引与图元

- `glDrawElements` 用索引复用顶点；索引类型 `u16`（≤65535 顶点）或 `u32`。
- 三角形绕序（CCW/CW）决定正面；`glFrontFace` + `glCullFace` 控制剔除。
- 条带（strip）/扇（fan）可省索引，但现代 GPU 上收益有限，且不利于合批。

### 9.3 顶点缓存优化

- GPU 有 post-transform cache（约 16–32 个顶点）；索引顺序影响命中率。
- 优化目标：让相邻三角形尽量复用顶点。工具：`meshoptimizer` 的 `optimizeVertexCache`。
- 过度优化收益有限，优先解决 DrawCall 与带宽。

### 9.4 蒙皮（Skinning）

```glsl
mat4 skin =
    a_weights.x * u_joints[int(a_joints.x)] +
    a_weights.y * u_joints[int(a_joints.y)] +
    a_weights.z * u_joints[int(a_joints.z)] +
    a_weights.w * u_joints[int(a_joints.w)];
vec4 world = u_model * skin * vec4(a_position, 1.0);
```

- 权重必须归一化（和为 1），否则模型会缩放。
- 骨骼矩阵通常是 `inverseBindPose * currentPose`。
- 移动端骨骼数受限，常用 **骨骼纹理（bone texture）** 代替 UBO 数组。
- 顶点数超过 4 根骨骼影响需要扩展属性或预烘焙。

### 9.5 LOD 与 HLOD

| 方案 | 说明 |
|---|---|
| 离散 LOD | 预生成 3–4 档，按屏幕占比切换 |
| 连续 LOD / 简化 | 运行时简化（成本高） |
| HLOD | 将远处多个物体合并为一个代理网格 |

车载导航/环视场景中，远景建筑常用 HLOD + impostor。

### 9.6 包围体与剔除

| 包围体 | 特点 |
|---|---|
| AABB | 便宜，旋转后需重算 |
| OBB | 更紧，测试更贵 |
| Sphere | 旋转不变，测试最便宜 |
| Convex Hull | 最紧，成本最高 |

**视锥剔除**：把包围体与 6 个视锥平面做测试。
**遮挡剔除**：硬件遮挡查询（`GL_ANY_SAMPLES_PASSED`）或软件 HZB。
**BVH**：把场景组织成层次包围盒，加速射线/视锥查询；ray tracing 与 GPU-Driven 剔除的基础。

### 9.7 SDF（有向距离场）

- 定义：点到最近表面的有符号距离。
- 用途：字体渲染（SDF 字体）、软阴影、体积效果、碰撞。
- 3D SDF 可用于 raymarching，但成本高；车载 HMI 更多用 2D SDF 字体与图标。

### 9.8 模型格式与资产管线

| 格式 | 特点 |
|---|---|
| glTF / GLB | 开放标准，PBR 友好，Web/移动通用 |
| FBX | DCC 交换事实标准，需转换 |
| OBJ | 简单，无动画/材质 |
| Draco | 几何压缩（glTF 扩展） |
| KTX2 / BasisU | 纹理压缩容器 |

**资产管线关键点**：单位统一（米）、坐标系统一（Y-up vs Z-up）、切线生成、材质映射（metal/rough）、LOD 生成、碰撞体生成。

## 10. 十二个高频问答

### Q1：为什么模型会"变黑"或"变平"？

> 常见原因：① 法线未归一化；② 法线用了模型矩阵而非逆转置；③ 光照方向空间不一致（世界空间法线配视图空间光）；④ 法线贴图的 Y 通道（OpenGL/DirectX 约定相反）；⑤ 纹理是 sRGB 却按线性采样。

### Q2：透视投影的深度为什么非线性？

> 透视除法除以 `w`（与距离相关），导致 `z_ndc` 与 `1/z` 成正比。近平面附近精度高，远处精度低。缓解：增大 near、使用反向 Z、对数深度缓冲。

### Q3：为什么透明物体要后往前画？

> Alpha 混合不满足交换律：`A over B ≠ B over A`。必须按视线方向从远到近绘制，才能得到正确结果。同时透明物体通常关闭深度写入，避免遮挡后面的透明物体。

### Q4：MSAA 和 FXAA 的区别？

> MSAA 在光栅化阶段对**几何覆盖**做多采样，每个像素仍只着色一次（或少数几次），对几何边缘有效；FXAA 是后处理，对**最终图像**做边缘检测与模糊，成本低但会让文字和细节变糊。TAA 用多帧抖动 + 重投影，能同时处理几何与着色锯齿，但会拖影。

### Q5：PBR 的金属度工作流和非金属度（specular/glossiness）有什么区别？

> 金属度工作流用 `baseColor + metallic + roughness`，非金属的 F0 固定 0.04，金属的 F0 取 baseColor，参数少、不易出错；specular/glossiness 直接给 F0 和光泽度，更灵活但容易做出非物理材质。两者可互相转换，但高光细节会丢失。

### Q6：为什么阴影会出现 acne？怎么解决？

> 阴影图分辨率有限，一个 texel 覆盖多个像素，加上深度精度误差，导致表面自比较失败。解决：slope-scaled depth bias、normal offset、提高阴影图分辨率、PCF 软化、以及把正面剔除改为背面渲染（peter-panning 折中）。

### Q7：CSM 解决什么问题？

> 单张 shadow map 覆盖整个视锥时，近处精度不足、远处浪费。CSM 按距离把视锥分段，每段独立一张图，近处高精度、远处低精度，并在级联边界做混合。

### Q8：前向渲染和延迟渲染怎么选？

> 灯少、透明多、移动端 → 前向；灯多、不透明为主、桌面 → 延迟；需要两者兼顾 → Forward+/Clustered。延迟的代价是 G-Buffer 带宽和 MSAA 困难；前向的代价是着色器变体和每物体灯光循环。

### Q9：为什么要做线性空间渲染？

> 光照的加乘运算在物理上对应线性光强；在 gamma 空间做会得到错误的亮度与混合结果（暗部过暗、混合发灰）。正确流程是纹理解码到线性 → 计算 → tone mapping → 编码输出。

### Q10：切线空间法线贴图为什么需要 TBN？

> 法线贴图存的是相对于表面的扰动，必须用该表面的切线/副切线/法线构成的基变换到世界空间。TBN 不正交或手性错误会导致光照方向整体偏移。

### Q11：蒙皮权重不归一化会怎样？

> 顶点会被缩放（权重和 < 1）或过冲（> 1），表现为模型"缩水"或"炸开"。导入管线必须校验并归一化。

### Q12：如何判断一个 3D 场景的瓶颈？

> 依次做：① 降分辨率（片元/带宽）；② 降顶点数或关闭部分模型（顶点/提交）；③ 关闭阴影/后处理（Pass 成本）；④ 用 RenderDoc/NSight/Arm Profiler 看时间轴与计数器。不要凭感觉优化。
