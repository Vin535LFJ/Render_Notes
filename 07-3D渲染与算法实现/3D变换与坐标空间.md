## 1. 坐标空间链

### 1.1 六个空间

| 空间 | 单位/原点 | 由谁定义 | 典型用途 |
|---|---|---|---|
| 模型空间（Local/Object） | 美术导出 | 建模软件 | 顶点原始坐标 |
| 世界空间（World） | 场景统一单位 | 引擎 | 摆放、光照、剔除 |
| 观察空间（View/Eye） | 相机在原点，看向 -Z（右手系） | 视图矩阵 | 相机相对位置、高光 |
| 裁剪空间（Clip） | 齐次坐标，`-w ≤ x,y,z ≤ w`（GL） | 投影矩阵 | 裁剪、透视除法前 |
| NDC | `[-1,1]` 或 `[0,1]` | 透视除法 + API 约定 | 屏幕映射输入 |
| 屏幕/窗口空间 | 像素 | 视口变换 | 光栅化 |

```
local --Model--> world --View--> eye --Projection--> clip --perspective divide--> NDC --Viewport--> window
```

### 1.2 顶点着色器的最小职责

```glsl
vec4 world = u_model * vec4(a_pos, 1.0);
vec4 eye   = u_view * world;
gl_Position = u_projection * eye;
```

- 传给片元的世界坐标/法线/切线必须单独输出，不能在片元里用 `gl_FragCoord` 反推。
- 透视正确插值由硬件完成：插值的是 `attr / w`，再在片元乘回 `w`，所以屏幕空间的线性插值不会让纹理在斜面上扭曲 ✅。

## 2. 矩阵与主序

### 2.1 列主序不等于"转置"

| 概念 | 含义 |
|---|---|
| 数学约定 | 列向量在右：`v' = M · v` |
| 内存布局 | 列主序：`m[0..3]` 是第一列 |
| GLSL/GLM | 列主序 + 列向量，`M * v`，`A * B` 表示先 B 后 A |
| HLSL | 默认行主序 + 行向量，`mul(v, M)`，`mul(A, B)` 表示先 A 后 B |
| Vulkan/Metal | 与 GLSL/HLSL 的数学约定无关，只认你上传的字节 |

**实践规则**：

- 用 GLM 时默认 `glm::mat4` 直接 `glUniformMatrix4fv(..., GL_FALSE, &m[0][0])`，不要手动转置。
- 从 HLSL/Unity 抄矩阵到 GLSL 时，最常见的错误是"看起来上下颠倒"——先确认是主序问题还是乘法顺序问题，不要盲目 `transpose`。
- 法线矩阵必须 `transpose(inverse(mat3(model)))`，这是唯一需要显式求逆的常用矩阵（§7）。

### 2.2 复合变换顺序

```
M = T · R · S        // 先缩放，再旋转，再平移
```

记住方法：矩阵从右往左作用于向量。把顺序写反，物体会绕世界原点而不是自身原点旋转。

## 3. 视图矩阵

### 3.1 lookAt 的构造

已知相机位置 `eye`、目标 `center`、上方向 `up`：

```cpp
vec3 f = normalize(center - eye);   // 前
vec3 s = normalize(cross(f, up));   // 右
vec3 u = cross(s, f);               // 校正后的上
```

右手系相机看向 **-Z**，因此视图矩阵的基是 `(s, u, -f)`：

```cpp
mat4 V = mat4(
    vec4(s.x, u.x, -f.x, 0.0),
    vec4(s.y, u.y, -f.y, 0.0),
    vec4(s.z, u.z, -f.z, 0.0),
    vec4(-dot(s, eye), -dot(u, eye), dot(f, eye), 1.0)
);
```

> GLSL 的 `mat4(...)` 按**列**填充：上面四行分别是第 0/1/2/3 列。写成"每行一个基向量"会得到转置矩阵，表现为相机旋转方向相反。

### 3.2 为什么是 -Z

OpenGL 的观察空间与裁剪空间都约定相机看向 -Z，这样标准透视矩阵的 `w_clip = -z_eye` 才能保证可见点 `w > 0`。Vulkan 沿用这一约定；D3D 左手系则看向 +Z，投影矩阵符号不同。跨 API 时**不要混用左右手系的投影矩阵**。

## 4. 投影矩阵

### 4.1 透视投影（OpenGL，右手系，NDC z ∈ [-1,1]）

令 `f = 1 / tan(fovY / 2)`，`n = near`，`far = f`（下文用 `N/F` 避免歧义）：

$$
P =
\begin{bmatrix}
\frac{f}{aspect} & 0 & 0 & 0 \\
0 & f & 0 & 0 \\
0 & 0 & \frac{F+N}{N-F} & \frac{2FN}{N-F} \\
0 & 0 & -1 & 0
\end{bmatrix}
$$

验证两个端点：

| `z_eye` | `z_clip` | `w_clip` | `z_ndc` |
|---|---|---|---|
| `-N` | `-N` | `N` | `-1` |
| `-F` | `F` | `F` | `+1` |

`w_clip = -z_eye`，所以透视除法后近大远小。**深度精度**的推导见 [光栅化深度与移动GPU架构 §2](../03-图形与GPU工程/光栅化深度与移动GPU架构.md#2-深度缓冲)。

### 4.2 透视投影（Vulkan / D3D，NDC z ∈ [0,1]）

保持右手系、`w = -z_eye` 不变，只把深度映射从 `[-1,1]` 改为 `[0,1]`：

$$
P_{[0,1]} =
\begin{bmatrix}
\frac{f}{aspect} & 0 & 0 & 0 \\
0 & f & 0 & 0 \\
0 & 0 & \frac{F}{N-F} & \frac{FN}{N-F} \\
0 & 0 & -1 & 0
\end{bmatrix}
$$

- `z_eye=-N → 0`，`z_eye=-F → 1` ✅。
- 如果直接把 GL 矩阵交给 Vulkan，画面会出现"近处被裁掉一半/深度全错"，因为负深度被裁掉。
- 常用补救：`VkPipelineViewportStateCreateInfo` 的负视口高度只能翻转 Y，**不能**把 `[-1,1]` 变成 `[0,1]`，深度范围必须在投影矩阵里改。

### 4.3 正交投影

GL（`[-1,1]`）：

$$
P_{ortho} =
\begin{bmatrix}
\frac{2}{R-L} & 0 & 0 & -\frac{R+L}{R-L} \\
0 & \frac{2}{T-B} & 0 & -\frac{T+B}{T-B} \\
0 & 0 & -\frac{2}{F-N} & -\frac{F+N}{F-N} \\
0 & 0 & 0 & 1
\end{bmatrix}
$$

Vulkan/D3D（`[0,1]`）只需把第三行改为：

$$
z_{ndc} = \frac{-z_{eye} - N}{F - N}
\quad\Rightarrow\quad
\begin{bmatrix} 0 & 0 & -\frac{1}{F-N} & -\frac{N}{F-N} \end{bmatrix}
$$

正交投影的 `w=1`，深度是线性的，不存在透视除法带来的精度挤压。2D/UI、阴影贴图（平行光）常用。

### 4.4 常见参数错误

| 现象 | 常见原因 |
|---|---|
| 物体被近平面裁掉 | `near` 设得过大；或用了 `[0,1]` 矩阵却按 GL 传 |
| 远处深度全糊成一片 | `far/near` 比值过大（如 0.1 / 10000） |
| 画面上下颠倒 | NDC Y 方向与视口 Y 方向不一致（§5） |
| 透视畸变异常 | `aspect` 用了屏幕像素比而非宽高比，或 FOV 单位是角度却当弧度 |
| 正交相机看不到物体 | 正交的 `N/F` 写成透视的符号 |

## 5. NDC 与视口：跨 API 差异表

| API | NDC x/y | NDC z | NDC Y 方向 | 帧缓冲原点 | 正面绕序（默认） |
|---|---|---|---|---|---|
| OpenGL / GLES | `[-1,1]` | `[-1,1]` | 向上 | 左下 | CCW |
| Vulkan | `[-1,1]` | `[0,1]` | **向下** | 左上 | 由 `VkFrontFace` 指定（常配 CW） |
| D3D 11/12 | `[-1,1]` | `[0,1]` | 向上 | 左上 | CW |
| Metal | `[-1,1]` | `[0,1]` | 向上 | 左上 | CW |
| WebGPU | `[-1,1]` | `[0,1]` | 向上 | 左上 | CCW |

> 表内是**默认**约定；Vulkan 的 Y 方向可通过负视口高度翻转，绕序可通过 `frontFace` 配置。跨 API 时以"最终像素落在哪"为准，不要只背表。

### 5.1 视口变换

GL 的窗口坐标：

$$
x_w = (x_{ndc} + 1) \cdot \frac{width}{2} + x_0, \qquad
y_w = (y_{ndc} + 1) \cdot \frac{height}{2} + y_0
$$

Vulkan 的 Y 向下，同一公式得到的是"从左上角量"的坐标：

$$
y_w = (y_{ndc} + 1) \cdot \frac{height}{2} + y_0
$$

配合 NDC Y 向下，最终图像方向正确。**不要**在 shader 里再翻一次 Y，否则会二次翻转。

### 5.2 纹理 UV 原点

| 来源 | 原点 | 处理 |
|---|---|---|
| OpenGL 纹理坐标 | 左下 | 默认 |
| PNG/JPEG/Bitmap 像素行 | 左上 | 上传时 `GL_UNPACK_FLIP_Y` 或 shader 里 `1.0 - v` |
| Android `Bitmap` | 左上 | `GLUtils.texImage2D` 不自动翻转 |
| Vulkan 图像 | 左上 | 采样坐标与 GL 相同，不需要翻 |
| FBO 颜色附件回读 | 左下（GL） | `glReadPixels` 得到的是倒置图 |

**统一策略**：在资源导入层决定一次 UV 约定，shader 里不再做条件分支。混用"有的纹理翻了、有的没翻"是 UI 图标上下颠倒的根因。

### 5.3 FBO 与 Y-flip 的典型事故

1. 用 GL 渲染到 FBO，再作为纹理采样：GL 的 FBO 纹理原点在左下，与窗口一致，通常**不需要**翻。
2. 用 `glBlitFramebuffer` 从 FBO 到默认帧缓冲：源/目标矩形都用左下原点，不要手动反转 `y0/y1`。
3. 把 GL 渲染结果交给 Vulkan/Android 合成器：两者原点不同，需要在边界处翻转（负视口高度或 blit 时交换 Y）。
4. 视频纹理（`GL_TEXTURE_EXTERNAL_OES`）的 UV 变换矩阵由 `SurfaceTexture.getTransformMatrix()` 给出，**不要**自己假设原点。

## 6. 视锥与剔除

### 6.1 从裁剪矩阵提取六个平面

对矩阵 `M = P · V`，其行向量 `r0..r3` 对应的视锥平面为（GLSL 是列主序，按行访问要取 `M[col][row]` 或先转置）：

| 平面 | 方程 |
|---|---|
| 左 | `r3 + r0` |
| 右 | `r3 - r0` |
| 下 | `r3 + r1` |
| 上 | `r3 - r1` |
| 近 | `r3 + r2`（GL） |
| 远 | `r3 - r2` |

平面系数需归一化后使用。用包围球测试时，保留条件为 `dot(n, c) + d >= -r`（保守剔除，允许少量误保留）。

### 6.2 为什么包围球测试会"误杀"

- 平面方程未归一化，`r` 的比较尺度不一致。
- 用了 AABB 的八个角点却只测一个角。
- 对跨近平面的大物体做保守裁剪时，直接丢弃整个物体会导致"贴脸消失"。正确做法是保留并与近平面求交（或交给 GPU 裁剪）。

## 7. 法线矩阵

### 7.1 为什么不能直接用模型矩阵

法线是**余切向量**，在非均匀缩放下不服从 `M · n`。正确变换是：

$$
N = (M^{-1})^{T}
$$

GLSL：

```glsl
mat3 normalMatrix = transpose(inverse(mat3(u_model)));
vec3 n = normalize(normalMatrix * a_normal);
```

### 7.2 何时可以省

| 模型变换 | 法线矩阵 |
|---|---|
| 只有平移 | 单位矩阵 |
| 旋转 + 均匀缩放 | `mat3(model)` 归一化即可 |
| 非均匀缩放 | 必须逆转置 |
| 含剪切 | 必须逆转置 |

**性能提示**：逆转置在 CPU 侧每帧算一次，作为 uniform 上传；不要在片元着色器里对每个像素求逆。

### 7.3 切线空间与 TBN

法线贴图采样得到的是切线空间法线，需要 TBN 矩阵转到世界空间：

```
T = normalize(mat3(model) * a_tangent)
N = normalMatrix * a_normal
B = cross(N, T) * a_tangent.w      // w 存储手性
mat3 TBN = mat3(T, B, N)
```

- 手性 `w` 必须从模型导入（MikkTSpace 约定），否则镜像 UV 的模型会出现法线反向。
- 只做法线贴图、不做各向异性时，可以只重建 `B = cross(N, T)`，但仍需保证 T 与 N 正交化。

## 8. 精度与常见 Bug 清单

| 现象 | 检查项 |
|---|---|
| 模型整体偏移/缩放错 | `M = T·R·S` 顺序；单位（米/厘米） |
| 相机旋转方向反了 | lookAt 矩阵是否被转置；`up` 与前向是否共线 |
| 深度全在近处 | 投影矩阵的 NDC 约定与 API 不匹配 |
| 画面上下颠倒 | NDC Y、视口 Y、纹理 UV 三处只允许翻一次 |
| 光照随缩放变暗/变亮 | 法线未用逆转置；或归一化遗漏 |
| 法线贴图左右反 | 切线手性 `w`；UV 是否镜像 |
| 远处 z-fighting | `far/near` 过大；未用 reversed-Z / 对数深度 |
| 裁剪后物体消失 | 视锥平面未归一化；或近平面保守剔除 |
| 多相机渲染错乱 | 视图/投影矩阵未按相机更新，仍用上一帧缓存 |

## 9. 自测问答

**Q1：MVP 三个矩阵各自解决什么问题？**
M 把模型放进世界，V 把世界搬到相机坐标系，P 把视锥压成规则裁剪体并产生透视。三者不能合并成一个矩阵上传吗？可以，但会失去逐物体剔除与精度控制，且法线矩阵仍需单独算。

**Q2：为什么透视除法能产生近大远小？**
裁剪空间 `w = -z_eye`，除以 w 后远处物体的 x/y 被压缩得更厉害。这不是"缩放"，是投影的几何结果。

**Q3：GL 的投影矩阵直接给 Vulkan 会怎样？**
Vulkan 的 NDC z 是 `[0,1]`，GL 是 `[-1,1]`。近平面附近 `z_ndc < 0` 的片元会被裁掉，表现为近处缺一块或深度测试全错。

**Q4：Vulkan 里负视口高度解决了什么？**
把 NDC 的 Y 向下翻成帧缓冲的 Y 向下，使图像方向与 GL 一致；它不改变深度范围，也不改变绕序（绕序要单独配 `frontFace`）。

**Q5：法线矩阵为什么是逆转置？**
法线要与变换后的表面保持垂直。若 `t` 是切向量、`n` 是法线，`M t · N n = t · n` 要求 `N = (M^{-1})^T`。非均匀缩放下 `M` 会把法线拉斜。

**Q6：正交投影需要透视除法吗？**
形式上仍除以 `w`，但正交矩阵的 `w=1`，所以深度与 xy 都是线性映射。

**Q7：纹理上下颠倒应该在哪一层解决？**
资源导入层统一约定一次。shader 里做 `1.0-v` 会让 FBO、视频纹理、UI 图集三套资源的约定互相冲突。

**Q8：为什么 near 不能设得太小？**
深度精度按 `1/z` 分布，`far/near` 越大，近处可用深度值越少。`near=0.01, far=1000` 的比值是 100000，16 位深度几乎必然 z-fighting。

**Q9：视锥剔除用包围球还是 AABB？**
包围球测试便宜、与旋转无关，适合粗剔除；AABB 更紧但需变换。工程上常先球后盒，或直接用 BVH。

**Q10：多相机（主视图 + 后视镜）要注意什么？**
每个相机独立的 view/projection 与视口；共享的只有场景数据。后视镜常需要镜像视图矩阵（翻转 X 或 Y），翻转后要同步调整正面绕序，否则被背面剔除。

---

> **一句话总结**：变换链的每个箭头都有明确的单位与手性；跨 API 事故几乎都来自"NDC 深度范围、Y 方向、UV 原点、矩阵主序"这四件事没有在边界处对齐。
