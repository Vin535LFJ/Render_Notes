## 1. 光照模型的演进

| 模型 | 公式核心 | 解决什么 | 遗留问题 |
|---|---|---|---|
| Lambert | `diffuse = N·L` | 漫反射随角度衰减 | 无高光、无能量守恒 |
| Phong | `spec = (R·V)^shininess` | 加高光 | 高光在低模上断裂 |
| Blinn-Phong | `spec = (N·H)^shininess` | 半角向量更便宜、更平滑 | 仍非物理 |
| PBR | 微表面 BRDF | 能量守恒、材质参数可测量 | 计算/带宽更贵 |

**面试要点**：Blinn-Phong 的 `H = normalize(L+V)` 用 `N·H` 替代 `R·V`，省一次反射向量计算，且高光形状更符合微表面直觉。但它的"高光强度"没有物理单位，调到好看即可；PBR 的 roughness 有明确含义（微表面法线分布宽度）。

## 2. 线性空间、单位与曝光

### 2.1 三条铁律

1. 光照计算必须在**线性光强**空间做。sRGB 纹理先解码，见 [色彩管理 §1](../03-图形与GPU工程/色彩管理与采样滤波.md#1-色彩空间与传输函数)。
2. 颜色纹理（albedo）是 sRGB；法线、粗糙度、金属度、AO 是**线性**数据，不能设 sRGB。
3. 光照结果经过 tone mapping 再编码到显示空间，不能把 HDR 值直接写进 8bit sRGB 附件。

### 2.2 曝光与单位

| 概念 | 说明 |
|---|---|
| 辐射度（radiance） | 单位立体角、单位面积的光功率，PBR 的物理量 |
| 曝光（exposure） | `color *= exposure`，模拟相机光圈/快门 |
| EV100 | `exposure = 1 / (1.2 * 2^EV100)` 一类约定，不同引擎常数不同 |
| 自动曝光 | 基于亮度直方图/对数平均，需时间平滑避免闪烁 |

> 点光/聚光的衰减在物理上是 `1/d²`。很多引擎为了美术可控改成 `1/(d² + ε)` 或加范围截断，这是**工程近似**，不是物理正确 ⚠️。

## 3. 微表面 BRDF

### 3.1 Cook-Torrance 分解

$$
f_r = \underbrace{\frac{1-\mathrm{metallic}}{\pi} \cdot \mathrm{albedo}}_{\text{漫反射}} +
\underbrace{\frac{D(h) \, G(l,v) \, F(v,h)}{4 (N\cdot L)(N\cdot V)}}_{\text{镜面反射}}
$$

| 项 | 作用 | 常用实现 |
|---|---|---|
| `D` | 微表面法线分布：多少微面朝向半角 | GGX / Trowbridge-Reitz |
| `G` | 几何遮蔽：微面互相遮挡 | Smith + Schlick-GGX |
| `F` | 菲涅尔：入射角越大反射越强 | Schlick 近似 |
| 分母 | 立体角与投影的归一化 | `4 (N·L)(N·V)` |

### 3.2 GGX 法线分布

$$
D_{GGX}(h) = \frac{\alpha^2}{\pi \left((N\cdot H)^2(\alpha^2-1)+1\right)^2},
\qquad \alpha = \mathrm{roughness}^2
$$

- `roughness` 是美术参数，`α` 是线性粗糙度；平方映射让低粗糙度区域变化更细腻（Epic 的约定）✅。
- 高光 lobe 随粗糙度变宽、变矮，总能量大致守恒。
- `N·H` 接近 0 时 `D` 很小，避免高光背面漏出。

### 3.3 几何项与菲涅尔

Smith-Schlick-GGX：

$$
G_1(x) = \frac{N\cdot X}{(N\cdot X)(1-k)+k},
\qquad
k = \frac{(\alpha+1)^2}{8} \text{（直接光）},\quad k=\frac{\alpha^2}{2}\text{（IBL）}
$$

Schlick 菲涅尔：

$$
F = F_0 + (1-F_0)(1 - V\cdot H)^5
$$

| 材质 | `F0` |
|---|---|
| 电介质（塑料、皮肤） | 约 0.04（4%） |
| 金属 | albedo 本身（0.5–1.0） |
| 混合工作流 | `F0 = mix(0.04, albedo, metallic)` |

> 常见错误：给金属加了漫反射。金属的自由电子会吸收透射光，**metallic=1 时 diffuse 必须为 0**，否则金属看起来像"发亮的塑料"。

### 3.4 metallic / roughness 工作流

```glsl
vec3 F0 = mix(vec3(0.04), albedo, metallic);
vec3 diffuseColor = albedo * (1.0 - metallic);
float alpha = roughness * roughness;
```

| 参数 | 物理含义 | 美术直觉 |
|---|---|---|
| baseColor/albedo | 电介质的漫反射色；金属的 F0 | 物体"本来是什么颜色" |
| metallic | 0=电介质，1=金属 | 是否导电/有自由电子 |
| roughness | 微表面粗糙程度 | 表面是镜面还是磨砂 |

### 3.5 能量守恒与多次散射

单次散射 BRDF 在粗糙度接近 1 时会损失能量（高光被微面互相遮挡后没有补回），表现为"粗糙金属发黑"。工程上常用 Fdez-Agüera 的多项散射近似（Filament 的写法）：

$$
F_{ms} = F_{ss} \cdot \frac{F_{avg}}{1 - E_{ms} F_{avg}},
\qquad
F_{avg} = F_0 + \frac{1-F_0}{21},
\qquad
E_{ms} = 1 - F_{ss}
$$

其中 `F_ss` 是单次散射的菲涅尔项（IBL 中为 `F0 * brdf.x + brdf.y`），`E_ms` 是单次散射能量。该式把损失的能量按平均值补回，粗糙金属不再发黑。

这是**近似**，不是严格物理 ⚠️；移动端常直接省略，用美术调参补偿。

## 4. IBL（基于图像的光照）

### 4.1 为什么需要

解析光源只能模拟点光/方向光。真实环境是全方位入射，PBR 必须处理**环境漫反射 + 环境镜面反射**。直接对 cubemap 做积分太贵，于是有了 split-sum 近似。

### 4.2 Split-Sum 近似

$$
\int L_i(l) f(l,v) (N\cdot l)\,dl
\approx
\underbrace{\int L_i(l)(N\cdot l)\,dl}_{\text{预滤波辐照度}} \times
\underbrace{\int f(l,v)(N\cdot l)\,dl}_{\text{BRDF LUT}}
$$

| 资源 | 内容 | 采样方式 |
|---|---|---|
| Irradiance map | 漫反射环境（低频） | 按法线采样，常用 SH9 代替 |
| Prefiltered env map | 镜面反射，按 roughness 分 mip | `mip = roughness * maxMip` |
| BRDF LUT | `(N·V, roughness) → (scale, bias)` | 2D 纹理，与场景无关 |

最终：

```glsl
vec3 R = reflect(-V, N);
vec3 prefiltered = textureLod(u_envMap, R, roughness * u_maxMip).rgb;
vec2 brdf = texture(u_brdfLUT, vec2(NdotV, roughness)).rg;
vec3 specular = prefiltered * (F0 * brdf.x + brdf.y);

vec3 irradiance = texture(u_irradianceMap, N).rgb;
vec3 diffuse = irradiance * diffuseColor;
```

### 4.3 工程细节

- 预滤波 cubemap 的 mip 链必须在**离线**或加载时生成，不能每帧算。
- 粗糙度到 mip 的映射不是严格线性，常见 `mip = roughness * (mipCount-1)` ✅ 近似。
- 高光采样时 `textureLod` 的 mip 需要三线性过滤，否则粗糙度变化会"跳层"。
- 移动端可用 SH9 存漫反射，省一张 cubemap；镜面仍需 cubemap 或平面反射。
- 环境贴图本身是 HDR（RGBE/BC6H/ASTC HDR），不能用 8bit sRGB 存，否则高光被截断。

## 5. 阴影

### 5.1 Shadow Map 基本原理

1. 从光源视角渲染深度到 `depthMap`。
2. 从相机视角把世界坐标变换到光源裁剪空间，得到 `lightNDC`。
3. 比较当前片元深度与 `depthMap` 中存储的深度：更远则处于阴影。

```glsl
vec3 proj = lightNDC.xyz / lightNDC.w;
proj = proj * 0.5 + 0.5;              // [-1,1] -> [0,1]（GL）
float closest = texture(u_shadowMap, proj.xy).r;
float current = proj.z;
float shadow = current - bias > closest ? 0.0 : 1.0;
```

### 5.2 偏差（Bias）

| 类型 | 公式/做法 | 作用 |
|---|---|---|
| 常数偏移 | `current - 0.005` | 简单，但斜面和远处会漏光/悬浮 |
| 斜率偏移 | `bias = max(0.05 * (1 - N·L), 0.005)` | 按入射角自适应 |
| 法线偏移 | 渲染 shadow map 时把顶点沿法线推一点 | 减少正面自阴影 |
| 正面剔除 | `glCullFace(GL_FRONT)` | 适用于封闭物体，避免背面深度被记录 |

> `bias` 调大消除自阴影，但会产生"彼得潘现象"（物体与影子分离）。没有一组参数能同时适配所有场景，必须按场景调 ⚠️。

### 5.3 PCF

```glsl
float shadow = 0.0;
vec2 texel = 1.0 / vec2(textureSize(u_shadowMap, 0));
for (int x = -1; x <= 1; ++x)
    for (int y = -1; y <= 1; ++y)
        shadow += current - bias > texture(u_shadowMap, proj.xy + vec2(x,y)*texel).r ? 0.0 : 1.0;
shadow /= 9.0;
```

- 3×3 PCF 只是把硬边变软，不是真正的软阴影。
- 更大的核（5×5、Poisson 采样）更平滑，但采样数平方增长。
- 硬件 `sampler2DShadow` + `GL_COMPARE_REF_TO_TEXTURE` 可以一次采样完成比较 + 双线性过滤 ✅。

### 5.4 CSM（级联阴影）

把相机视锥按距离切成 N 段，每段一张 shadow map：

| 级联 | 覆盖范围 | 分辨率 | 用途 |
|---|---|---|---|
| 0 | 0–10 m | 高 | 近处细节 |
| 1 | 10–30 m | 中 | 中景 |
| 2 | 30–80 m | 低 | 远景 |
| 3 | 80–200 m | 最低 | 超远/地形 |

关键工程点：

- **分割方案**：实用分割（practical split）用对数与均匀混合，避免近处级联太窄。
- **稳定级联**：光源矩阵按纹素对齐（把投影原点量化到 texel 网格），否则相机动一点阴影就"爬行"。
- **级联选择**：按相机空间深度选级联，边界处做淡入淡出，避免硬切换。
- **分辨率预算**：4 张 2048² 的深度图在移动端可能已占几十 MB，需要按平台降级。

### 5.5 其他阴影技术

| 技术 | 优点 | 代价/限制 |
|---|---|---|
| VSM | 可免费模糊、软阴影 | 漏光（light bleeding），需修正 |
| ESM | 指数深度，模糊便宜 | 偏移敏感，易过曝 |
| PCSS | 按遮挡物距离估软硬 | 采样多 |
| Contact Shadow | 屏幕空间补近处接触阴影 | 仅屏幕内，厚度假设 |
| Ray-traced Shadow | 物理正确 | 硬件要求高，见 P2 |

## 6. 环境光遮蔽（AO）

| 类型 | 原理 | 适用 |
|---|---|---|
| Baked AO | 离线烘焙到顶点/纹理 | 静态场景，质量最高 |
| SSAO | 屏幕空间深度采样估计遮蔽 | 动态场景，便宜但有噪点/边缘光晕 |
| HBAO/GTAO | 改进采样与去噪 | 质量更好，成本更高 |
| RTAO | 光追 | 高端平台 |

**PBR 中的 AO 用法**：AO 只应调制**环境光/IBL**，不应直接乘到直接光上。直接光的遮蔽已经由阴影表达：

```glsl
vec3 ambient = (diffuseIBL + specularIBL) * ao;
vec3 color = ambient + directLighting * shadow;
```

> 常见错误：`color *= ao` 把所有光照一刀切，导致阴影区域过暗、直接光也失去层次。

## 7. 前向、延迟与混合管线

### 7.1 对比

| 维度 | Forward | Deferred | Forward+ / Tiled | Clustered |
|---|---|---|---|---|
| 光照遍历 | 每物体遍历所有灯 | 每像素遍历所有灯 | 每 tile 建灯列表 | 3D cluster 建灯列表 |
| G-buffer 带宽 | 无 | 高（多张 RT） | 中（depth prepass） | 中 |
| MSAA | 友好 | 昂贵/困难 | 友好 | 友好 |
| 透明物体 | 原生支持 | 需单独 forward pass | 支持 | 支持 |
| 材质多样性 | 高 | 受 G-buffer 布局限制 | 高 | 高 |
| 移动端 TBDR | 友好 | 需 on-chip G-buffer 或 PLS | 友好 | 较复杂 |

### 7.2 Deferred 的 G-buffer 布局

典型布局（可压缩）：

| 附件 | 内容 | 格式 |
|---|---|---|
| RT0 | albedo.rgb + metallic | RGBA8 |
| RT1 | normal.xy + roughness + AO | RGBA8（法线用 octahedral 编码） |
| RT2 | 自发光/材质 ID | RGBA8 |
| Depth | 深度/模板 | D24S8 / D32F |

带宽估算：1080p、4 张 RGBA8 = `1920×1080×4×4 ≈ 33 MB/帧` 的写入，加上读取与混合，很容易超过移动端预算。**这是移动端慎用 Deferred 的核心原因** ✅。

### 7.3 Forward+ 的深度预pass

1. Depth prepass：只写深度，不写颜色，提前做 Early-Z。
2. 计算着色器按 tile（如 16×16）统计灯光影响范围，生成 light grid。
3. 正常 forward pass 按像素所在 tile 只遍历相关灯。

优点：MSAA 友好、透明物体可用、灯多时仍可控。代价：多一次几何提交与深度带宽。

### 7.4 移动端 TBDR 的特殊性

TBDR 的 on-chip tile memory 让"G-buffer 留在片上"成为可能（PLS / framebuffer fetch），但：

- 片上内存有限（通常每 tile 几十 KB），G-buffer 布局必须压缩。
- 一旦 tile 的 attachment 被 store 到系统内存，带宽优势消失。
- 因此移动端更常见的是 **Forward + 深度预pass + 少量灯光**，而不是桌面式 Deferred ⚠️。

详见 [光栅化深度与移动GPU架构 §4](../03-图形与GPU工程/光栅化深度与移动GPU架构.md#4-移动-gpu-架构tbdr-vs-imr)。

## 8. 材质系统与 Shader 变体

| 概念 | 说明 |
|---|---|
| Material | 参数集合（颜色、纹理、粗糙度） |
| Pass | 一次绘制状态（混合、深度、着色器） |
| Shader Variant | 同一 shader 因宏/关键字生成的排列组合 |
| Keyword | `_NORMALMAP`、`_SHADOWS` 等编译开关 |

**变体爆炸**：10 个布尔关键字 = 1024 个变体。治理手段：

- 用位掩码/uber shader + 动态分支（移动端谨慎）。
- 只保留实际使用的组合（构建期扫描场景）。
- 按画质档位裁剪（低端机不编译高光/阴影变体）。
- PSO 预热见 [批处理与GPU驱动管线 §9](批处理与GPU驱动管线.md#9-pso-预热与变体治理)。

## 9. 调试清单

| 现象 | 排查顺序 |
|---|---|
| 整体发灰/发白 | 颜色纹理是否 sRGB；是否在线性空间光照；tone mapping 是否重复 |
| 金属像塑料 | metallic 是否为 1；diffuse 是否被清零；F0 是否用了 albedo |
| 高光过曝/死白 | HDR 缓冲位深；曝光；Bloom 阈值；是否在 sRGB 空间做 bloom |

| 阴影漏光/条纹 | bias、shadow map 分辨率、级联范围、法线偏移 |
| 阴影边缘爬行 | 级联是否按纹素对齐；光源矩阵是否每帧重算 |
| AO 过黑 | AO 是否乘到了直接光；AO 纹理是否被当 sRGB |
| 透明物体无光照 | Deferred 管线是否漏了 forward pass |
| 移动端发热/掉帧 | G-buffer 带宽；overdraw；灯光数量；是否触发了 tile store |

## 10. 自测问答

**Q1：Lambert 和 PBR 的本质区别？**
Lambert 只有漫反射且不守恒；PBR 用微表面 BRDF 同时建模漫反射与镜面反射，满足能量守恒与菲涅尔，参数有物理含义。

**Q2：为什么金属没有漫反射？**
金属的自由电子会吸收进入内部的折射光，透射光无法散射回来，只剩表面反射。因此 metallic=1 时 diffuse=0，颜色体现在 F0。

**Q3：GGX 的 α 为什么是 roughness²？**
让美术参数在低粗糙度区间有更细腻的感知变化，同时让高光 lobe 的宽度与能量分布更接近实测材质。这是 Epic 的工程约定 ✅。

**Q4：Split-sum 近似牺牲了什么？**
忽略了环境贴图与 BRDF 的耦合（假设两者可分离），在强方向光环境、极粗糙/极光滑表面会有偏差；工程上通过预滤波与 LUT 补偿 ⚠️。

**Q5：阴影 bias 为什么不能一劳永逸？**
bias 要同时对抗自阴影（需要大）和彼得潘现象（需要小），两者随场景尺度、光照角度、shadow map 分辨率变化，只能按场景调。

**Q6：CSM 的级联边界为什么会闪？**
相邻级联的分辨率与投影不同，切换时采样位置跳变。解决：按深度淡入淡出、纹素对齐、重叠区域混合。

**Q7：AO 应该乘在哪？**
只乘环境光/IBL。直接光的可见性由阴影负责；把 AO 乘到直接光会重复遮蔽。

**Q8：Deferred 为什么不适合移动端？**
G-buffer 多附件写入/读取带来巨大外部带宽，而 TBDR 的片上内存又放不下完整 G-buffer；MSAA 在 Deferred 下也更贵。

**Q9：Forward+ 解决了 Forward 的什么问题？**
Forward 每个物体要遍历所有灯，灯多时 shader 复杂度和 uniform 上传爆炸；Forward+ 用 tile light list 把每像素的灯数降下来。

**Q10：如何判断高光是不是"物理正确"？**
看三点：能量是否守恒（粗糙金属不发黑）、菲涅尔是否随视角增强、粗糙度是否只改变 lobe 宽度而不改变总能量。目测之外，用 BRDF LUT 或渲染方程参考图对比。

> **一句话总结**：PBR 不是"更复杂的 Phong"，而是把材质拆成可测量的物理量；阴影、AO、IBL 各自负责一种可见性/入射光，混用它们的调制对象是画面"脏"的主要原因。
