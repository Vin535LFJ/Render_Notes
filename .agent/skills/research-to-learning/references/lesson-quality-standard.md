# 教材质量标准（lesson-quality-standard）

> P6.4 交付物 · 2026-11-18。**状态：已采纳为可迭代统一基准（D12 B3，2026-11-19 人工裁决）； Gold Standard L01 样板地位待 B4 人工阅读确认。** 十维度诊断结论仅为线索，不替代人工评分。
> 适用对象：`courses/*/lessons/*.md` 教学版教材。参考样章：`courses/video-rendering-journey/lessons/L01-为什么视频不是-RGB.md`（P6 Gold Standard）。
> 与既有门禁的关系：`check_chapter_arc.py` 是**结构性底线**（五要素存在性），`validate_site.py` 是**数据一致性底线**；本标准是**语义质量要求**，由人工审核（G2/G3）与 AI 诊断程序共同执行，自动校验不能代替语义审查。

---

## 1. 先分清四种文体

| 文体 | 写作目标 | 成功判据 |
|---|---|---|
| 技术参考文档 | 准确、完整、可查 | 结论有出处，边界条件齐全 |
| **系统教材** | 让学习者循序渐进地**理解** | 读者不查外部资料也能完成本章理解闭环 |
| 操作手册 | 让读者照做能成功 | 步骤可复现 |
| 面试题库 | 让读者能表达 | 结论+原理+约束+反例四段式 |

它们引用同一份知识（单一来源，D06），但**教材不是参考文档的压缩版**。教材可以用自己的语言解释概念、推导原理、设计教学案例、建立直观理解；禁止的是把主文档整篇复制进课程目录，不是禁止展开。

**"不复制"≠"不展开"**：关键机制用"详见源文档，此处不复制"一句带过，是 P6 诊断发现的首要病因。教材必须在本章内完成理解闭环，链接用于权威出处与延伸，不是理解的替代品。

## 2. 十维度质量检查（诊断与写作共用）

1. **开篇真实问题**：钩子来自真实场景/反直觉现象/具体数字张力，不是"本章介绍 X"。
2. **知识动机**：每个核心知识点回答"不学它会遇到什么问题"；动机先于定义。
3. **前置自然引入**：先修知识在用到之前被唤起（一句话复习或链接），不假设读者记得。
4. **新概念不突现**：术语首次出现有一句话解释或术语链接；记号（如 4:2:0）要解释含义再使用。
5. **因果逐层推导**：从问题到结论有可跟随的推理链；关键机制给出推导而非结论句（例：stride 错位要推出"逐行累积 n×padding"，而不是只说"会花屏"）。
6. **直观模型**：抽象概念有类比或可观察现象支撑，且**声明类比边界**（见 §4）。
7. **图解与公式**：数据形态有图（ASCII/表格/实验截图均可）；公式给符号含义、数值算例、工程后果三件套；数字口径精确（MB/MiB 不混读，说比例必带基准）。
8. **真实工程案例**：至少一个可复述的工程现场（故障排查/平台差异/性能取舍），由源文档事实重组，不编造。
9. **可验证实践**：实验/练习真正验证本章目标；优先利用 `tools/labs.json` 已定义的 tasks/selfTest 设计观察点，给出"做什么→预期看到什么→对应哪个机制"。
10. **下一章承接**：桥句说明"本章解决了 X，但一旦需要 Y，X 就不够了"；与课程路线数据（course.json next）一致。

## 3. 每章必须回答的六问（教学叙事）

- 为什么在这里介绍这个知识？（路线位置）
- 不学它会遇到什么问题？（动机）
- 前面哪些知识帮助理解？（前置唤起）
- 新概念如何一步步推导出来？（因果链）
- 它与实际系统有什么关系？（工程案例）
- 它为下一章解决什么问题创造了条件？（桥）

## 4. 类比纪律

- 类比必须服务于理解，且**准确**：流水线→GPU Pipeline、仓库+钥匙→共享缓冲区、电影院→PTS 显示调度、排班表→RenderGraph。
- 每个类比附**边界声明**：类比在哪里失效（例："涂色底图"不是存储格式本身，U/V 是具体色度数值）。
- 不得为了生动编造技术事实；类比中的技术细节仍须可追溯到源文档或断言。

## 5. 数学与工程关联

- 每个公式三件套：**符号含义 → 数值算例 → 工程后果**（例：stride 公式 → 1080@128=1152 → 斜纹/绿线机制）。
- 推导深度按知识类型裁剪（§6），但"只给结论不给推导"仅适用于结论级源文档且明确标注"机制细节见锚点"的情形；源文档有完整推导的（如投影矩阵），教材应重组关键步骤。
- 数字纪律：精确字节数优先；MB/MiB 分开；比例带基准；[测试数据-仅供参考] 与 [AI-生成] 标记的内容不得写成确定事实。

## 6. 按知识类型选结构，不强制统一标题

十二段模板（assets/lesson-template.md）是**骨架参考**，不是检查清单。按知识类型灵活组织：

| 知识类型 | 重心 | 典型结构 |
|---|---|---|
| 概念直觉型（YUV、零拷贝） | 直观模型 + 数据形态图 | 问题→类比→机制→布局图→误区→实验 |
| 数学推导型（MVP、投影） | 逐层推导 + 算例 | 问题→空间链→推导→数值验证→跨 API 差异→实验 |
| 工程机制型（RenderGraph、同步） | 因果链 + 边界条件 | 问题→失控场景→机制→何时不值得→案例→实验 |
| 对比边界型（软/硬解、GL/Vulkan） | 差异表 + 适用条件 | 问题→对比维度→平台差异→选择判据→实验 |

唯一硬性要求：arc 五要素（hook/prerequisite/concepts/bridge/practice）存在且**实质成立**，frontmatter schema 完整。

## 7. 引用与断言纪律

- **引用必须真实**："源文档有 X 说明"必须真的有 X；小节号/锚点必须核对（P6 发现 L02"分级处置"不存在、L06"§7.3"错位，均为 blocker/major）。
- 重要技术结论挂断言（frontmatter `claims` + 正文 `V##` 引用）；**不得借挂不相关断言凑追溯**（P6 发现 L13 把 MVP 顺序挂在"可编程阶段"断言上）。
- 新断言按 `evidence-and-claims.md` 程序登记，AI 提取/生成的一律默认 `open`，人工 G1 升级；正文以主文档锚点为权威依据，并在术语节说明断言状态。
- 无出处的历史叙事/背景知识：明确标注为背景叙述，列入候选断言清单，不冒充已验证结论。
- quiz 的 `claim_ids` 必须与题目内容相关且 ⊆ 课时 claims（validate §11b）；参考答案给依据，不只给结论。

## 8. 主动学习设计

每章包含（形式按类型裁剪）：思考问题、主动回忆（合上文档复述因果链）、数学推导练习、实验观察任务、工程案例复盘、自我检测（回指 checkpoint/quiz）、延伸学习。自我检测题与 course.json checkpoint 保持一致（改题须四处联动：两层 course.json + 正文 + quiz）。

## 9. 诊断程序（P7 逐篇复用）

1. 通读正文 + frontmatter + quiz，按 §2 十维度逐项判定（✓/部分/✗ + 说明）。
2. **逐条对源**：正文每个技术表述找到源文档行号；标记"无出处/夸大/错位/过度简化"。
3. 跨层核对：两层 course.json 目标与 next、ledger claims/used_by、labs.json 绑定、quiz 挂接。
4. 问题分级：blocker（事实/追溯错误）/ major（显著影响理解或一致性）/ minor（润色/记录）。
5. 产出逐章问题清单（含证据行号与修复方案），汇入 `教材质量诊断.md`；修复一次一篇，过门禁，留人工审核材料。
6. **AI 诊断不是评分**：诊断结论只作线索；正式评分（25/25/20/20/10，总分≥85 且事实/连贯各≥80%）由人工填写，AI 不得自批。

## 10. 阅读体验

- 段落短、每节先说"解决什么问题"再给结论；代码块带注释与恢复默认值等工程细节。
- 图用 ASCII/表格优先（离线站零依赖约束）；公式用 `$$…$$`（站点保护）。
- 术语链接指向知识锚点或术语表，不指向无关文档；实验链接用 `#/lab/<id>`。
- 篇幅以理解闭环为准（Gold Standard L01 约 300 行），不以行数凑深度，也不以"精简"为由砍推导。
