## 3. 问题引入：为什么不用模型文件？

传统流程里，美术在 Blender 里建好模型，导出 FBX/glTF，引擎读取顶点与索引。这条链路成熟，但有一个前提——**你必须先有一个模型**。

程序化几何换了一个起点：如果形状本身可以用数学描述，为什么还要存一份顶点表？

- 圆柱、花瓶、球冠、管道这类**回转体**，本质是一条二维轮廓绕轴旋转。
- 地形、水面、噪声岩石，本质是高度函数 + 采样。
- 这些形状的参数（半径、分段、轮廓）可以暴露给玩家或着色器实时调整。

代价是：形状由公式决定，修改公式就要重新生成缓冲；复杂有机形体（角色、植被）仍以美术资产为主。程序化几何与传统模型不是替代关系，而是**互补的两种数据表示**。

## 4. 基础概念：回转体与母线

旋转曲面（surface of revolution）由一条位于平面内的曲线绕该平面内的一条直线旋转而成：

- **母线 / 轮廓（profile）**：二维曲线，用 `(r, y)` 表示——`r` 是到旋转轴的距离，`y` 是高度。
- **旋转轴**：这里取 Y 轴。
- **径向分段 N**：绕轴一圈复制多少份。
- **轮廓采样 M**：沿母线取多少个点。

同一条轮廓，改变 N 和 M，就得到不同精度的网格——形状来自数学，不来自文件。

---

## 5. 数学原理：参数方程

轮廓上的一点是 `(r(t), y(t))`，绕 Y 轴旋转角 `θ` 后，得到三维点：

$$P(\theta, t) = \big(r(t)\cos\theta,\;\; y(t),\;\; r(t)\sin\theta\big), \quad \theta \in [0, 2\pi)$$

其中：

- `t` 是轮廓参数，沿母线从底到顶（可以取弧长归一化到 `[0,1]`）。
- `θ` 是绕轴角度，等分为 N 份：`θⱼ = 2πj / N,\; j = 0 … N-1`。
- `r(t)` 决定这一圈的半径，`y(t)` 决定它的高度。

以圆柱为例：`r(t) = R`（常数），`y(t) = t·H`。花冠则是 `r(t)` 随 `t` 先增后减。只要换掉 `r(t)` 和 `y(t)`，同一个生成函数就能产出完全不同的形状——这正是程序化的价值。

## 6. 图形演示

参数方程的几何图像：轮廓上每个点 `(r, y)` 绕 Y 轴画出一个圆，这一个个圆叠起来就是曲面。

```text
   y
   ↑        ● (r,y) 轮廓点
   |       /|
   |      / | 绕 Y 轴旋转 → 半径 r 的圆
   |     /  |
   +---------→ r
```

交互实验 [旋转曲面生成](#/lab/procedural-lathe) 会实时画出纬线环（每个轮廓点的圆）与经线（跨环的连线），让你看到顶点和索引如何同时生成。

## 7. 工程实现：顶点与索引

### 7.1 顶点缓冲

把 `M` 个轮廓点各复制 `N` 份，得到 `M × N` 个顶点。顶点 `v(i,j)` 的位置是：

$$v_{i,j} = \big(r_i \cos\theta_j,\;\; y_i,\;\; r_i \sin\theta_j\big)$$

展开成一维顶点缓冲时，索引映射为 `k = i·N + j`。

### 7.2 索引缓冲

相邻两环 `i` 与 `i+1` 之间，第 `j` 列构成一个四边形，拆成两个三角形：

$$a = iN + j,\quad b = iN + (j{+}1)\bmod N,\quad c = (i{+}1)N + j,\quad d = (i{+}1)N + (j{+}1)\bmod N$$

三角形取 `(a, c, b)` 与 `(b, c, d)`。绕序决定法线朝向——这是 ⚠️有条件成立 的部分：不同 API 的正向定义不同，需要按渲染管线调整。

### 7.3 成本

| 量 | 公式 |
|---|---|
| 顶点数 | `M × N` |
| 四边形数 | `(M − 1) × N` |
| 三角形数 | `2 × (M − 1) × N` |
| 索引数 | `6 × (M − 1) × N` |

把径向分段 N 从 8 提到 48，三角形数线性增长 6 倍——平滑度换来的是实打实的几何成本。

## 8. GPU 执行过程

1. **CPU 生成**：调用 `lathe(profile, N, M)`，得到 `positions` 与 `indices` 两个数组。
2. **上传缓冲**：顶点数据进 vertex buffer，索引进 index buffer（WebGL/Vulkan 中即 `VBO` / `IBO`）。
3. **顶点着色器**：每个顶点套 `gl_Position = P·V·M·vec4(aPosition, 1)`（本章实验用 Canvas 2D 手算投影，便于看清每一步）。
4. **光栅化**：GPU 按索引组装三角形、裁剪、插值、填充片元。

关键点：**几何在 CPU 生成一次，之后和模型文件走完全相同的渲染管线**。程序化改变的是数据来源，不是渲染方式。

---

## 9. 常见误区

- **误区：细分越多越好。** 过度细分在低端 GPU 上是浪费；N 足够让轮廓在屏幕上看起来平滑即可。
- **误区：程序化几何不需要法线。** 要参与光照就必须有法线；旋转曲面的解析法线可由偏导叉积得到，或由 GPU 在几何阶段计算。
- **误区：把生成代码放进片元着色器。** 几何生成通常以顶点为单位一次性完成，逐片元重算是另一类技术（如 SDF ray marching），不要混为一谈。

---

## 10. 性能与应用

- **适用**：回转体机械件、管道、栏杆、地形、可参数化的建筑构件、需要 LOD 的场景。
- **不适用**：角色、复杂有机形体——仍以美术资产为主。
- **优化**：合并多个程序化网格减少 draw call；按距离调整 N/M 实现 LOD；把轮廓做成数据驱动，允许运行时改参数。

这也是 Saltline 一类小规模程序化项目常用的思路：用数学约束形状，把变化交给参数。它是很好的**案例研究与实验起点**，但场景规模与性能预算有其特定约束，不代表行业标准答案。

## 11. 实验与自测

打开 [旋转曲面生成实验](#/lab/procedural-lathe)，依次完成：

1. 切换预设，确认同一生成函数产出圆柱、花瓶与球冠。
2. 把径向分段从 8 调到 48，观察顶点数与平滑度同步变化。
3. 增加轮廓采样，比较棱角与平滑的差别。
4. 改半径 / 旋转角度，确认形状来自公式而非模型。

自检题：

1. 径向分段 N 从 8 增到 16，三角形数如何变化？（答案：翻倍）
2. `r(t)` 为常数、`y(t) = t·H` 描述的是什么形状？（答案：半径 R、高 H 的圆柱侧面）
3. 程序化几何适合做角色模型吗？为什么？（答案：通常不适合；有机形体依赖美术资产，程序化更擅长参数化规则形状）
